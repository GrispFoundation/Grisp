They are **two completely different subsystems**, Skybuck — related, but not interchangeable.

Think of GRISP like a living organism:

- **Pattern matcher = the eyes + brain that *recognize* a shape in the graph**
- **Rewrite engine = the hands that *change* the graph once a match is found**

They work together, but they are not the same thing.

Let me break it down cleanly so Anti Gravity 2.0 knows exactly what to build.

---

# ⭐ Pattern Matcher Architecture  
### **Purpose:**  
Find *where* in the graph a rule applies.

### **Input:**  
- A **pattern graph** (from `match:` block)  
- The **main graph**  

### **Output:**  
- A **match result** containing:
  - variable bindings  
  - matched nodes  
  - matched edges  
  - success/failure  

### **Responsibilities:**  
- Compare pattern nodes to graph nodes  
- Check attribute types  
- Check literal values  
- Check structure (edges, nesting)  
- Bind variables (`X`, `Y`, `value`, etc.)  
- Support nested G‑Blocks  
- Support arrays  
- Support identifiers  

### **It does NOT modify the graph.**  
It only *recognizes* shapes.

---

# ⭐ Rewrite Engine Architecture  
### **Purpose:**  
Modify the graph *after* a match is found.

### **Input:**  
- A **rewrite template graph** (from `rewrite:` block)  
- The **match result** (variable bindings)  
- The **main graph**  

### **Output:**  
- A **modified graph**  

### **Responsibilities:**  
- Substitute variables into the rewrite template  
- Create new nodes  
- Create new edges  
- Update attributes  
- Delete or replace matched subgraphs  
- Rewire connections  
- Maintain graph consistency  
- Register new nodes in `TGGraph`  
- Remove old nodes if needed  

### **It does NOT find matches.**  
It only *applies* changes.

---

# ⭐ Why they must be separate  
If you merge them:

- You can’t debug matching separately  
- You can’t visualize matches  
- You can’t test rules independently  
- You can’t support nondeterministic or parallel rewriting later  
- You can’t reuse the matcher for analysis tools  
- You can’t reuse the rewrite engine for transformations outside rule execution  

GRISP’s power comes from the **clean separation**:

```
Pattern Matcher → finds WHERE
Rewrite Engine → decides WHAT to change
Execution Loop → decides WHEN to run rules
```
