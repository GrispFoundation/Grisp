# ⭐ **GRISP 1.0 — Anti Gravity 2.0 Build Specification**  
*(Graph Rewrite Information Symbolic Processor, using G‑Blocks)*

---

# 1. Purpose and Scope

Anti Gravity 2.0 must build a **complete GRISP 1.0 system**, consisting of:

- A **G‑Blocks parser**  
- A **graph engine** (`TGNode`, `TGEdge`, `TGGraph`, `TGValue`)  
- A **pattern matcher**  
- A **rewrite engine**  
- A **runtime loop**  
- Optional **visual/debug hooks**  

GRISP 1.0 is a **graph‑native symbolic programming system** where:

- Programs are graphs  
- Data is graphs  
- Rewrite rules are graphs  
- Execution is graph rewriting  

The canonical syntax is **G‑Blocks**.

The implementation language for v1 is **Delphi**.

---

# 2. Core Data Model (Delphi)

Anti Gravity 2.0 must generate the following Delphi classes exactly:

### 2.1 `TGValue`
Represents a typed value from G‑Blocks.

- `Kind: TGValueKind`  
- `NumberValue: Double`  
- `StringValue: string`  
- `BoolValue: Boolean`  
- `IdentifierValue: string`  
- `ArrayValue: TObjectList<TGValue>`  
- `NodeValue: TGNode`  

### 2.2 `TGNode`
Represents a G‑Block node.

- `Id: Integer`  
- `Name: string`  
- `NodeType: string`  
- `Attributes: TObjectDictionary<string, TGValue>`  
- `Outgoing: TObjectList<TGEdge>`  

### 2.3 `TGEdge`
Represents a labeled, typed connection.

- `LabelName: string`  
- `EdgeType: string`  
- `Source: TGNode`  
- `Target: TGNode`  

### 2.4 `TGGraph`
Represents a complete GRISP program.

- `Nodes: TObjectList<TGNode>`  
- `Edges: TObjectList<TGEdge>`  
- `NodeIndex: TObjectDictionary<string, TGNode>`  
- `Rules: TObjectList<TGNode>`  
- `AddNode`, `AddEdge`, `FindNode`, `RegisterRule`

These classes are the **foundation** of GRISP.

# 3. G‑Blocks Syntax (Canonical Input Format)

Anti Gravity 2.0 must parse the following syntax:

```
node <Name> {
    <EdgeName>: <Type> = <Value>
    ...
}
```

### Supported types:
- `number`
- `string`
- `boolean`
- `identifier`
- `array<T>`
- `node` (nested block)

### Supported values:
- literals (`5`, `"Hello"`, `true`)
- identifiers (`tool.math.add`)
- arrays (`[1,2,3]`)
- nested nodes (`node = { ... }`)

The parser must:

- tokenize  
- parse  
- validate types  
- build `TGNode` + `TGValue` + `TGEdge` objects  
- insert them into a `TGGraph`

Anti Gravity 2.0 must support:

### Tool definition
```

    a: number
    b: number
    returns: number
}
```

### Tool call
```

    tool: identifier = tool.math.add
    a: number = 5
    b: number = 7

```

### Tool result
```

    value: number = 12
}
```

These are represented as normal `TGNode` objects.

# 5. Rewrite Rules (Core of GRISP)

Rewrite rules are G‑Blocks nodes whose name starts with `rule.`.

Example:

```
node rule.simplify.add.zero {
    match: node = {
        op: identifier = add
        left: identifier = x
        right: number = 0
    }

    rewrite: node = {
        value: identifier = x
    }
}
```

Anti Gravity 2.0 must:

- Parse `match` into a **pattern graph**  
- Parse `rewrite` into a **replacement graph**  
- Store the rule in `TGGraph.Rules`  

---

# 6. Pattern Matching Engine

Anti Gravity 2.0 must generate a matcher that:

- Takes a **pattern graph** and a **target graph**  
- Supports:
  - variable binding  
  - literal matching  
  - type matching  
  - nested structure matching  
- Returns:
  - success/failure  
  - variable bindings  

Matching is **structural graph unification**.

---

# 7. Rewrite Engine

Anti Gravity 2.0 must generate:

`ApplyRule(RuleNode: TGNode; Graph: TGGraph)`

Steps:

1. Extract `match` pattern  
2. Extract `rewrite` template  
3. Try to match pattern in graph  
4. If match succeeds:
   - substitute variables into rewrite template  
   - build replacement subgraph  
   - splice into main graph  
   - update edges, attributes, nodes  

---

# 8. Execution Model

Anti Gravity 2.0 must generate:

`Run(Graph: TGGraph; MaxSteps: Integer)`

Loop:

1. For each rule in `Graph.Rules`:
   - Try to apply rule  
   - If applied → mark change  
2. Stop when:
   - no rule matches  
   - or max steps reached  

Mode: **deterministic** for v1.

# 10. Minimal Example Anti Gravity 2.0 Must Support

Input:

```
node A {
    value: number = 1
    next: identifier = B
}

node B {
    value: number = 2
}

node rule.swap-if-greater {
    match: node = {
        X: node = {
            value: number = 2
            next: identifier = Y
        }
        Y: node = {
            value: number = 1
        }
    }

    rewrite: node = {
        X: node = {
            value: number = 1
            next: identifier = Y
        }
        Y: node = {
            value: number = 2
        }
    }
}
```

Expected:

- Parser builds graph  
- Rule is registered  
- Pattern does not match initially  
- If values are swapped, rule fires
