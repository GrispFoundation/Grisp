GARP/1.24 DeepSeek Fix v6

Root cause confirmed from live trace:
- Session preparation succeeds.
- InjectPrompt fails after ~53 ms with INPUT_VERIFICATION_FAILED.
- Therefore the failure occurs before send-button submission.
- The generic ProviderAdapter native textarea value setter is being overwritten by DeepSeek's controlled composer state.

Fix:
- DeepSeekAdapter now overrides inject().
- Uses execCommand("selectAll") + execCommand("insertText") for the controlled composer.
- Dispatches InputEvent + change.
- Strictly verifies the resulting textarea value.
- Retries up to three times.
- Does not synthesize Enter or submit inside inject(); existing submitVerified() remains responsible for the provider send action.
- Existing DeepSeek send-button and message verification improvements from v5 are retained.
