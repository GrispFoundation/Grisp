=====================================
GRISP SPECIFICATION DEVELOPMENT AGENT
GSDA/3.1
=====================================

Identifier:  GSDA/3.1
Status:      Proposed normative specification
Supersedes:  GSDA/3.0 and all earlier GSDA revisions
Purpose:     Cooperative development, analysis, critique, repair, refinement,
scoring, convergence, publication, and deterministic replay of
technical specifications using multiple untrusted LLM reasoning
peers under a deterministic kernel.
Domain:      Pure specification development.
Non-domain:  Compilation, execution, debugging, runtime inspection, LSP,
tree-sitter, static analysis of target programs, target-program
execution, OS execution by the deterministic kernel, GRISP
execution, arbitrary external software-development tools,
arbitrary network access.
Default:     Fail-closed for structural, identity, integrity, governance,
resource, authentication, replay, and publication failures.

GSDA/3.1 is a hardening release over GSDA/3.0.

===============================================
0. NORMATIVITY, KEYWORDS, AND META-REQUIREMENTS
===============================================

[Informative] GSDA distinguishes normative requirements, informative prose,
and structured data.

[Informative] A normative requirement is a machine-readable Requirement
record with a stable requirement_id.

[Informative] Informative prose explains the system and does not itself
impose mandatory behaviour when it begins with [Informative].

[Informative] Structured data consists of records representing state,
evidence, provenance, configuration, identity, or other machine-readable
values.

REQ-GSDA-META-001
Every mandatory GSDA behaviour MUST be represented as a Requirement record,
except the META-00xx bootstrap family, which is governed by the pinned
bootstrap schema.

REQ-GSDA-META-002
Every structured GSDA record MUST declare its schema identifier.

REQ-GSDA-META-003
A record with an unknown or unsupported schema identifier MUST be rejected
with SCHEMA_FAILURE.

REQ-GSDA-META-004
Every structured GSDA record type MUST be present in the authoritative
schema registry.

REQ-GSDA-META-005
The schema language MUST be JSON Schema Draft 2020-12.

REQ-GSDA-META-006
A schema MUST declare additionalProperties = false unless the registry
explicitly declares that schema extensible and provides the x_gsda_ext
object.

REQ-GSDA-META-007
Unrecognized properties MUST cause SCHEMA_FAILURE unless admitted through
an explicitly declared x_gsda_ext object.

REQ-GSDA-META-008
The rendered specification MUST be derived from spec.requirements.json.

REQ-GSDA-META-009
The rendered specification MUST NOT introduce mandatory behaviour that is
absent from spec.requirements.json.

REQ-GSDA-META-010
META-00xx MUST be validated in bootstrap pass zero against the
kernel-trusted bootstrap schema.

REQ-GSDA-META-011
After bootstrap pass zero, META-00xx records MUST also pass ordinary schema
validation.

REQ-GSDA-META-012
requirement_id MUST be unique across the complete requirement set.

REQ-GSDA-META-013
The specification MUST ship RunNormativeKeywordLinter.

REQ-GSDA-META-014
The normative-keyword set is exactly:

MUST
MUST NOT
SHALL
SHALL NOT
SHOULD
SHOULD NOT
MAY
REQUIRED
RECOMMENDED
NOT RECOMMENDED
OPTIONAL

REQ-GSDA-META-015
A normative keyword outside a Requirement block MUST either occur in an
exempt keyword-definition paragraph or in a paragraph whose first token is
[Informative].

REQ-GSDA-META-016
An unmarked normative keyword MUST produce NORMATIVE_KEYWORD_LEAK and MUST
block publication.

REQ-GSDA-META-017
Requirement-block recognition MUST use the exact requirement_id values from
spec.requirements.json.

REQ-GSDA-META-018
The linter MUST NOT infer whether prose is normative by semantic analysis.

REQ-GSDA-META-019
The specification package MUST ship one authoritative registry containing
error codes, named failures, evidence kinds, identity classes, publication
predicates, and test classes.

REQ-GSDA-META-020
Registry identifiers MUST be unique within their respective namespace.

=================
1. PRIORITY ORDER
=================

Priority order:

1. USER_INTENT_PRESERVATION
2. CONSISTENCY
3. COMPLETENESS
4. PRECISION
5. TRACEABILITY
6. TESTABILITY
7. CLARITY
8. CONCISENESS
9. STYLE

REQ-GSDA-PRI-001
When two candidate changes create a genuine quality conflict, the
coordinator MUST prefer the higher-priority property.

REQ-GSDA-PRI-002
A lower-priority improvement MUST NOT silently weaken a higher-priority
property.

REQ-GSDA-PRI-003
The priority order MUST NOT control scheduling, round ordering, or
resource allocation unless an operation explicitly declares a genuine
quality conflict.

REQ-GSDA-PRI-004
Operation-specific tie-breaking MUST occur only after the priority order
fails to distinguish the alternatives.

REQ-GSDA-PRI-005
A Coordinator Decision resolving a quality conflict MUST record
priority_tipping.

REQ-GSDA-PRI-006
Only an authorized human decision MAY explicitly override the priority
order.

REQ-GSDA-PRI-007
A priority override MUST name the affected priority levels and provide a
non-empty rationale.

========
2. SCOPE
========

REQ-GSDA-SCOPE-001
GSDA MUST remain a pure specification-development system.

REQ-GSDA-SCOPE-002
The deterministic kernel MUST NOT require a compiler, target runtime,
debugger, language server, tree-sitter, target-program static analyzer,
or arbitrary external software-development tool.

REQ-GSDA-SCOPE-003
Execution of GSDA's own deterministic conformance tests is in scope.

REQ-GSDA-SCOPE-004
Execution of any target program or implementation artifact being specified
is out of scope.

REQ-GSDA-SCOPE-005
Only explicitly configured LLM providers MAY be contacted over a network.

REQ-GSDA-SCOPE-006
The kernel MUST NOT invoke arbitrary external network endpoints.

REQ-GSDA-SCOPE-007
The kernel MUST NOT spawn processes.

REQ-GSDA-SCOPE-008
The kernel MUST NOT directly perform OS-boundary package export operations.

REQ-GSDA-SCOPE-009
Package export MUST be performed only by the package exporter component.

REQ-GSDA-SCOPE-010
The package exporter MUST NOT modify authoritative coordinator state.

TESTABILITY: TESTABLE

=======================
3. TRUST BOUNDARY MODEL
=======================

Trust zones:

T0  External world
T1  LLM provider
T2  Peer adapter
T3  Validated input store
T4  Deterministic kernel
T5  Authoritative state
T6  Human acceptance
T7  Published revision

REQ-GSDA-TRUST-001
Normal data flow MUST be:

T0 -> T1 -> T2 -> T3 -> T4 -> T5 -> T6 -> T7

REQ-GSDA-TRUST-002
T5 MAY be read by T4 through declared kernel operations.

REQ-GSDA-TRUST-003
T1 MUST NOT directly access T4.

REQ-GSDA-TRUST-004
T1 MUST NOT write T5.

REQ-GSDA-TRUST-005
T2 MUST NOT write T5.

REQ-GSDA-TRUST-006
T2 MAY write only T3 and raw-response storage explicitly assigned to T2.

REQ-GSDA-TRUST-007
Every trust-boundary crossing MUST be represented in provenance.

REQ-GSDA-TRUST-008
Every T1 payload MUST remain untrusted until validated by T4.

REQ-GSDA-TRUST-009
No T1 payload MAY directly become authoritative state.

REQ-GSDA-TRUST-010
Authoritative state MUST be created or changed only by kernel operations.

REQ-GSDA-TRUST-011
A kernel input without validated T3 provenance MUST be rejected with
PROTOCOL_FAILURE.

REQ-GSDA-TRUST-012
A human decision MUST not directly mutate authoritative state. The kernel
MUST validate the decision and then apply the corresponding state change.

4. IDENTITY CLASSES
===================

Identity classes:

SEMANTIC_DETERMINISTIC
EXECUTION_DETERMINISTIC
COORDINATOR_ASSIGNED
DERIVED_EXECUTION

REQ-GSDA-IDC-001
A SEMANTIC_DETERMINISTIC identity MUST depend only on its declared semantic
inputs.

REQ-GSDA-IDC-002
A SEMANTIC_DETERMINISTIC identity MUST NOT depend on run_id, peer_id,
round_id, logical_sequence, wall-clock time, transport state, random data,
or mutable history.

REQ-GSDA-IDC-003
An EXECUTION_DETERMINISTIC identity MAY depend on declared execution
context including run_id, peer_id, round_id, and logical identifiers.

REQ-GSDA-IDC-004
run_id and peer_id MUST be COORDINATOR_ASSIGNED.

REQ-GSDA-IDC-005
round_id MUST be DERIVED_EXECUTION.

REQ-GSDA-IDC-006
Every deterministic identity formula MUST list every input field.

REQ-GSDA-IDC-007
An undeclared field MUST NOT influence a deterministic identity.

REQ-GSDA-IDC-008
Implementation-defined ordering MUST NOT influence any deterministic
identity.

REQ-GSDA-IDC-009
Wall-clock time MUST NOT influence SEMANTIC_DETERMINISTIC identity.

REQ-GSDA-IDC-010
All deterministic identity algorithms MUST be executable without network,
LLM, OS file-system, locale, or implementation-defined collation services.

==========================
5. GLOBAL CANONICALIZATION
==========================

REQ-GSDA-NORM-001
GSDA canonicalization MUST use a GSDA canonical JSON profile based on
RFC 8785.

REQ-GSDA-NORM-002
GSDA object keys MUST be ordered by UTF-8 bytewise lexicographic order.

REQ-GSDA-NORM-003
The UTF-8 bytewise key order in REQ-GSDA-NORM-002 is the authoritative GSDA
order and MUST be used consistently for all GSDA canonicalization.

REQ-GSDA-NORM-004
Duplicate JSON object keys MUST be rejected before canonicalization.

REQ-GSDA-NORM-005
NaN and Infinity MUST be rejected.

REQ-GSDA-NORM-006
Negative zero MUST normalize to zero where numeric normalization applies.

REQ-GSDA-NORM-007
Identity-bearing GSDA records MUST contain integer JSON numbers only.

REQ-GSDA-NORM-008
Identity-bearing records containing floating-point JSON values MUST cause
SCHEMA_FAILURE.

REQ-GSDA-NORM-009
GSDA schemas MUST NOT define float_tolerant fields.

REQ-GSDA-NORM-010
Provider floating-point output MAY be converted by an adapter into an
integer field only before kernel validation and only where the payload
schema declares the destination integer field.

REQ-GSDA-NORM-011
Adapter conversion of a provider floating-point value MUST use
round-half-to-even and MUST emit FLOAT_ROUNDED evidence.

REQ-GSDA-NORM-012
The kernel MUST never accept floating-point data as an authoritative
numeric value.

REQ-GSDA-NORM-013
canonical_record_jcs(X) MUST include the GSDA record's schema field.

REQ-GSDA-NORM-014
canonical_identity_object(X) MUST use the same canonical JSON profile but
is defined for transient identity-preimage objects.

REQ-GSDA-NORM-015
canonical_file_json(X) MUST canonicalize a parsed JSON value without
injecting a schema property.

REQ-GSDA-NORM-016
All integer division required by GSDA MUST be floor division.

REQ-GSDA-NORM-017
All timestamps MUST use:

YYYY-MM-DDTHH:MM:SS.sssZ

REQ-GSDA-NORM-018
Timestamps MUST be excluded from semantic identities.

REQ-GSDA-NORM-019
All arrays declared sorted MUST use the global GSDA bytewise identifier
ordering unless the containing algorithm explicitly defines another order.

REQ-GSDA-NORM-020
Locale-sensitive ordering MUST NOT be used.

REQ-GSDA-NORM-021
Case folding MUST NOT occur during general canonicalization.

REQ-GSDA-NORM-022
NFC MUST be applied only where the applicable field or algorithm explicitly
declares NFC comparison.

6. SEMANTIC PROJECTION
======================

[Informative] SemanticProjection exists to prevent accidental inclusion of
operational metadata in content identities.

REQ-GSDA-SP-001
Every content-addressed record schema MUST declare a semantic projection.

REQ-GSDA-SP-002
The semantic projection MUST explicitly enumerate the fields participating
in the record's content identity.

REQ-GSDA-SP-003
Fields not present in the semantic projection MUST NOT influence
content_id.

REQ-GSDA-SP-004
Provenance fields MUST NOT participate in content_id unless explicitly
declared semantic by the schema.

REQ-GSDA-SP-005
Authentication fields MUST NOT participate in semantic content identity
unless explicitly declared semantic by the schema.

REQ-GSDA-SP-006
logical_sequence MUST NOT participate in semantic content_id.

REQ-GSDA-SP-007
created_at MUST NOT participate in semantic content_id.

REQ-GSDA-SP-008
Every semantic projection MUST be represented in the schema registry.

REQ-GSDA-SP-009
Two records with identical semantic projections MUST have identical
content_id.

8. TERM NORMALIZATION
=====================

REQ-GSDA-NORM-030
term_id normalization MUST be:

NFC
-> trim
-> Unicode casefold
-> collapse internal whitespace runs to "-"
-> replace remaining non [a-z0-9-] with "-"
-> collapse repeated "-"
-> strip leading/trailing "-"
-> lowercase

REQ-GSDA-NORM-031
An empty term_id MUST cause SCHEMA_FAILURE.

REQ-GSDA-NORM-032
Stored term text MUST NOT be rewritten by normalization.

REQ-GSDA-NORM-033
Term comparison MUST compare term_id.

REQ-GSDA-NORM-034
General requirement text MUST NOT be normalized before glossary lookup.

REQ-GSDA-NORM-035
Term collision detection MUST occur before a normalization collision can
silently replace one raw term with another.

10. INTENT EXTRACTION
=====================

REQ-GSDA-INTENT-001
ExtractIntentElements MUST accept user_prompt, user_intent, and the
configured segmentation policy.

REQ-GSDA-INTENT-002
HYBRID segmentation MUST apply:

1. explicit marker boundaries;
2. sentence boundaries;
3. RFC 2119 pre-keyword boundaries;
4. minimum-fragment merging;
5. deterministic overlap resolution;
6. explicit intent-loss reporting.

REQ-GSDA-INTENT-003
Markers MUST use longest-match-first.

REQ-GSDA-INTENT-004
marker_prefixes MUST be prefix-free.

REQ-GSDA-INTENT-005
Overlap resolution MUST use:

earliest byte_start
longest segment
bytewise-smallest text

REQ-GSDA-INTENT-006
Discarded segments MUST produce OVERLAP_DISCARDED evidence.

REQ-GSDA-INTENT-007
Unrepresentable source fragments MUST produce INTENT_LOSS_DETECTED
evidence and F_INSUFFICIENT_COVERAGE.

REQ-GSDA-INTENT-008
Intent extraction MUST NOT call an LLM.

REQ-GSDA-INTENT-009
Identical input and identical policy MUST produce identical
IntentElements.

18. AGGREGATION
===============

For criterion k and artifact r:

Participation:

Participating(i,r,k) iff
selected score exists
AND confidence >= 1
AND peer is not excluded by self-score rule.

N(r,k) =
sum R(i,k) * C(i,r,k) * W(k) * S(i,r,k)

D(r,k) =
sum R(i,k) * C(i,r,k) * W(k)

If D(r,k) > 0:

A(r,k) = N(r,k) div D(r,k)
A_rem(r,k) = N(r,k) mod D(r,k)
denom(r,k) = D(r,k)
status = DEFINED

If D(r,k) = 0 and participating peers exist:

A(r,k) = sum(S) div n
A_rem(r,k) = sum(S) mod n
denom(r,k) = n
status = DEFINED
emit LOW_RELIABILITY_AGGREGATE

If no participating peers exist:

A(r,k) = 0
A_rem(r,k) = 0
denom(r,k) = 0
status = UNDEFINED

Overall:

K = all defined criteria

If K is empty:

status = UNDEFINED

Else:

N(r) =
sum w(k) * (A(r,k) * denom(r,k) + A_rem(r,k))

D(r) =
sum w(k) * denom(r,k)

A(r) = N(r) div D(r)
A_rem(r) = N(r) mod D(r)
denom(r) = D(r)
status = DEFINED

REQ-GSDA-AGG-001
Undefined criteria MUST NOT silently become zero.

REQ-GSDA-AGG-002
Undefined criteria MUST be explicitly represented.

REQ-GSDA-AGG-003
All-undefined overall aggregates MUST be UNDEFINED.

REQ-GSDA-AGG-004
Configured criterion weights MUST be preserved in provenance.

19. EXACT RATIONAL COMPARISON
=============================

REQ-GSDA-RAT-001
CompareRationalAggregate MUST compare:

A1 + R1/D1
A2 + R2/D2

where:

D1 > 0
D2 > 0
0 <= R1 < D1
0 <= R2 < D2

REQ-GSDA-RAT-002
The comparator MUST first compare A1 and A2.

REQ-GSDA-RAT-003
Only equal A values MAY proceed to remainder comparison.

REQ-GSDA-RAT-004
Remainder comparison MUST calculate:

L = R1 * D2
R = R2 * D1

REQ-GSDA-RAT-005
Each cross product MUST be checked for overflow.

REQ-GSDA-RAT-006
When direct cross multiplication would overflow, each fraction MUST be
reduced independently using:

g1 = gcd(R1, D1)
g2 = gcd(R2, D2)

and:

R1' = R1 / g1
D1' = D1 / g1
R2' = R2 / g2
D2' = D2 / g2

REQ-GSDA-RAT-007
The comparator MUST retry cross multiplication once after reduction.

REQ-GSDA-RAT-008
If the reduced comparison still exceeds the selected arithmetic bound,
the implementation MUST fail with AGGREGATION_BOUNDS_EXCEEDED.

REQ-GSDA-RAT-009
The comparator MUST NOT fall back to A-only comparison after overflow.

REQ-GSDA-RAT-010
The comparator MUST return:

-1 if aggregate 1 < aggregate 2
0 if aggregate 1 = aggregate 2
+1 if aggregate 1 > aggregate 2

REQ-GSDA-RAT-011
The comparator MUST be symmetric and transitive.

REQ-GSDA-RAT-012
UNDEFINED aggregates MUST be filtered before comparison.

reliability, scheduling, or publication semantics MUST use a major
version increment.

REQ-GSDA-MIG-003
Pre-migration replay MUST use the original semantics and configuration.

REQ-GSDA-MIG-004
Every migration MUST include at least one MIGRATION conformance case.

REQ-GSDA-MIG-005
The migration from GSDA/3.0 to GSDA/3.1 MUST document at minimum:

bootstrap trust-root protocol
semantic projection
global ordering definition
removal of float-tolerant schemas
reduced adapter salvage
human signature authentication
explicit logical ordering
explicit resource floors
target_context_id
corrected term collision timing
explicit traceability identity
staged package freeze/commit semantics
C0/C1/C2 conformance
critical-intent retention
explicit reference semantics gate

REQ-GSDA-MIG-006
3.0 semantic identities MUST NOT silently be reinterpreted as 3.1
identities.

REQ-GSDA-MIG-007
A 3.0 object migrated to 3.1 MUST either retain its historical identity
for audit or receive a new 3.1 identity with an explicit migration link.

TESTABILITY: TESTABLE

57. SECURITY INVARIANTS
=======================

REQ-GSDA-SEC-001
Peer authentication MUST prevent peer impersonation.

REQ-GSDA-SEC-002
Human authentication MUST prevent unauthorized acceptance under the
configured Level 2 authentication profile.

REQ-GSDA-SEC-003
An adapter MUST NOT create authoritative decisions.

REQ-GSDA-SEC-004
A peer MUST NOT select the authoritative aggregate.

REQ-GSDA-SEC-005
A peer MUST NOT change an immutable artifact after submission.

REQ-GSDA-SEC-006
A package exporter MUST write only inside the assigned staging root.

REQ-GSDA-SEC-007
Package path traversal MUST be rejected.

REQ-GSDA-SEC-008
Reparse-point traversal MUST be rejected unless explicitly admitted by a
security profile stricter than the base requirements.

REQ-GSDA-SEC-009
Case and Unicode filesystem ambiguity MUST NOT change package identity.

REQ-GSDA-SEC-010
An accepted frozen package MUST NOT be replaced by a different package
before commit.

REQ-GSDA-SEC-011
A package-integrity mismatch MUST fail closed.

REQ-GSDA-SEC-012
Peer-supplied diagnostic content rendered by a human-review interface
MUST be output-encoded so it cannot alter document structure or executable
UI interpretation.

===========================================
61. INFORMATIVE: WHAT GSDA DOES NOT PROMISE
===========================================

[Informative] GSDA does not promise objective truth in arbitrary domains.

[Informative] GSDA does not promise deterministic LLM generation.

[Informative] GSDA does not guarantee perfect specification completeness.

[Informative] GSDA does not treat consensus as proof.

[Informative] GSDA does not treat reliability as truth.

[Informative] GSDA does not claim that distinct models are philosophically
or epistemically independent.

[Informative] GSDA does not eliminate human judgment.

[Informative] GSDA does provide deterministic kernel semantics, explicit
identity, preserved uncertainty, auditable provenance, bounded resources,
deterministic replay, governed package publication, and machine-checkable
conformance.

====================================
62. INFORMATIVE: CENTRAL ABSTRACTION
====================================

[Informative] The central abstraction is:

LLMs produce evidence.
Adapters establish transport-safe inputs.
The kernel establishes deterministic facts.
The coordinator manages authoritative state.
Reliability weights qualifying evidence.
Humans resolve epistemic uncertainty.
The package binds the accepted result.
The revision preserves governed history.

[Informative] No individual model is the specification.

[Informative] No individual model is the final reviewer.

[Informative] No score is proof.

[Informative] No reliability value is authority.

[Informative] No consensus is proof.

63. INFORMATIVE: FINAL PRINCIPLE
================================

[Informative] GSDA is a deterministic governance shell around
non-deterministic reasoning workers.

[Informative] Determinism belongs to the kernel.

[Informative] Reasoning belongs to the peers.

[Informative] Governance belongs to the human-controlled acceptance
process.

[Informative] Publication belongs to the frozen package commitment and
its integrity gate.

to become the authority.
