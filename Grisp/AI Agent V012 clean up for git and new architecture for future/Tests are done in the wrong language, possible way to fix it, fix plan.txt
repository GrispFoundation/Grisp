### Why the agent/test harness ends up asking for C tests
1. **Default/example prompts**: The help text and examples include C prompts. If a test harness or user copies examples, C becomes the de facto default.  
2. **No language preference stored or signaled**: The CLI has no `--lang` or `--language` option and does not set a capability that restricts outputs to Pascal/Delphi. Without that, any downstream component (peers, adapters, or automated test suites) can choose C.  
3. **External orchestrator behavior**: The agent appears designed to coordinate multiple LLM peers and adapters. Those peers or the harness that drives the agent may be configured to request C test programs for validation or unit tests. The CLI itself only forwards tasks; it doesn’t validate the requested language.
