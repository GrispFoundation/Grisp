### Issues and risks to address first
Below are the highest priority items that could cause incorrect behavior, security holes, or brittle operation.

#### Capability and VFS gaps
- **Path normalization is implemented in capability root only** but not shown for arbitrary VirtualPath inputs in VFS. Every VFS method must canonicalize and validate paths before any filesystem operation.  
- **Drive letter and UNC handling** must be enforced in the VFS layer, not only in capability roots. The VFS should reject any path containing a colon after normalization.  
- **Symlink and hardlink escapes** are not addressed. The physical mapping must ensure the sandbox directory is isolated and that symlink resolution cannot escape the sandbox. Use realpath or equivalent and verify prefix.  
- **MIME detection** is string based. Relying on client supplied MIME is unsafe. Use content sniffing or a trusted mapping from file extension to allowed MIME. Validate both.

#### GRISP execution and harness
- **ValidatePlan returns only Diagnostics string** but no structured error codes. The harness should return structured validation results including which capability failed and why.  
- **ExecutePlan lacks resource caps** in the stub. Real execution must enforce CPU, memory, file descriptor, and wall time limits per plan.  
- **No explicit sandboxing mechanism** is implemented. The plan references Docker or similar, but the adapter must be hardened to avoid privilege escalation.

#### Concurrency and state
- **Coordinator and GRISP components are not thread safe** as written. If you run multiple tasks concurrently, shared structures like TGrispCapabilitySet and TGrispGraph need synchronization.  
- **Peer calls are synchronous**. Real LLM clients should be called asynchronously with timeouts and cancellation to avoid blocking the coordinator.

#### Error handling and robustness
- **Many methods assume success** and do not check return values. For example, FVfs.Resolve is used without verifying the file exists or that WriteFile succeeded.  
- **Memory ownership for TDictionary fields** in records is not consistently managed. Records that own TDictionary must implement proper creation, copying, and freeing semantics to avoid leaks and double frees.  
- **JSON serialization and deserialization** is referenced but not implemented. You need robust serializers that validate fields and handle missing or malformed data from LLMs.

#### Security and adversarial behavior
- **LLM outputs are treated as structured objects** but LLMs can hallucinate fields or craft malicious payloads. All peer outputs must be validated and sanitized before use.  
- **Capability requests from peers must be rate limited and audited** to prevent a malicious peer from forcing heavy debug runs. Implement budget and approval policies.

#### Testing and CI
- **Unit tests are planned but not present**. Critical units to test first are VFS path normalization, capability validation, sandbox mapping, and the parser.  
- **Fuzz tests for path inputs and GRISP surface language** are essential to find edge cases.

### Concrete fixes and code suggestions
Below are prioritized, actionable changes and small code patterns to integrate.

#### 1. Harden VFS Resolve and WriteFile
- Canonicalize input path, reject colon characters, resolve symlinks, ensure physical path starts with sandbox root.

```delphi
function TGrispVfs.ResolveSafe(const VirtualPath: string; out RealPath: string; out Reason: string): Boolean;
var
  Canon: string;
  Phys: string;
begin
  Canon := StringReplace(VirtualPath.Trim, '\', '/', [rfReplaceAll]);
  if Pos(':', Canon) > 0 then
  begin
    Reason := 'Drive letters not allowed';
    Exit(False);
  end;
  if (Canon.Contains('..')) then
  begin
    Reason := 'Relative traversal not allowed';
    Exit(False);
  end;
  // Map to sandbox root
  Phys := TPath.Combine(FSandboxRoot, Canon.TrimStart(['/']));
  Phys := TPath.GetFullPath(Phys);
  // Resolve symlinks if platform supports
  if not Phys.StartsWith(FSandboxRoot) then
  begin
    Reason := 'Path escapes sandbox';
    Exit(False);
  end;
  RealPath := Phys;
  Result := True;
end;
```

#### 2. Enforce content based MIME validation
- Use file extension mapping and optionally a lightweight content sniff for scripts and binaries.

#### 3. Structured validation results
- Replace ValidatePlan signature with a record that includes `Accepted: Boolean`, `FailedOps: TArray<string>`, `Diagnostics: string`.

#### 4. Thread safety and async peers
- Use `TTask` or a thread pool for peer calls. Protect shared lists with `TCriticalSection` or `TMonitor`.

```delphi
TTask.Run(
  procedure
  var
    Candidate: TCandidate;
  begin
    Candidate := Peer.GenerateCandidate(UserPrompt);
    TMonitor.Enter(FCandidatesLock);
    try
      FCandidates.Add(Candidate);
    finally
      TMonitor.Exit(FCandidatesLock);
    end;
  end
);
```

#### 5. Ownership for dictionaries in records
- Convert records that own objects into classes or implement explicit lifecycle functions.

```delphi
type
  TRepair = class
  private
    FMetadata: TDictionary<string,string>;
  public
    constructor Create;
    destructor Destroy; override;
    property Metadata: TDictionary<string,string> read FMetadata;
  end;
```

#### 6. Capability negotiation policy engine
- Implement a small policy module that computes activation score per capability using request counts, risk keywords, and remaining budget. Log decisions.

#### 7. Robust serializers
- Implement `ToJson` and `FromJson` for each record with strict validation and schema checks. Reject unknown fields or unexpected types.

#### 8. Resource enforcement in harness
- Use containerization with seccomp, user namespaces, and cgroups. The adapter should spawn containers with explicit limits and a read only host mount for the sandbox root.
