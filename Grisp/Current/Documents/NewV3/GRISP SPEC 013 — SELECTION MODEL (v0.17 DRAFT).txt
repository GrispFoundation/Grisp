GRISP SPEC 013 — SELECTION MODEL (v0.17 DRAFT)

Status: Draft
Layer: 0 (Deterministic Core)
Depends on: Spec 001 Canonical IR, Spec 006 Match Discovery Model, Spec 012 Tick Model, Spec 014 Dependency Set Model

Purpose:
This specification defines the deterministic Selection Model for GRISP. The Selection Model chooses exactly one match per tick from the set of discovered matches. Selection must be deterministic, fair, reproducible, and independent of engine implementation details. All engines must select the same match for the same state and Canonical IR.

1. Overview
The Selection Model assigns each match a deterministic score. The score is computed from:
- base priority
- match age
- fairness boost
- tie-break component
The match with the highest score is selected. If multiple matches have the same score, deterministic tie-breaking rules apply.

2. Base Priority
Each rule has a base priority defined in the Canonical IR. Base priority is an integer. Higher values indicate higher priority. Base priority is the first component of the score.

3. Match Age
Match age is the number of ticks since the match was first discovered. Match age starts at 0 when the match is first discovered. Match age increments by 1 at the end of each tick in which the match remains valid. Match age resets to 0 when:
- the match fires
- the match becomes invalid
- the match is rediscovered after invalidation
Match age is used to ensure fairness.

4. Fairness Boost
The fairness boost is computed as:
fairness_boost = match_age * fairness_factor
The fairness_factor is a constant defined as 1 in v0.17. The fairness boost ensures that long-waiting matches eventually fire even if they have lower base priority.

5. Tie-Break Component
The tie-break component is computed from the match_key. The match_key is hashed using a deterministic hash function. The hash is converted to a fixed-point integer. The tie-break component ensures deterministic ordering among matches with identical priority and fairness.

6. Score Computation
The score for a match is computed as:
score = base_priority * priority_scale + fairness_boost * fairness_scale + tie_break * tie_break_scale
The scale constants are:
priority_scale = 1,000,000
fairness_scale = 1,000
tie_break_scale = 1
These constants ensure that:
- base priority dominates fairness
- fairness dominates tie-break
- tie-break resolves final ties

7. Deterministic Hash Function
The hash function used for tie-break must be:
- deterministic
- stable across engines
- stable across platforms
- stable across versions
The hash function must operate on the match_key string. The hash must produce a 32-bit integer. The hash must not depend on memory layout or pointer values.

8. Selection Algorithm
The selection algorithm is:
1. For each match, compute score.
2. Select the match with the highest score.
3. If multiple matches have the same score, select the one with the smallest match_key lexicographically.
4. Return the selected match.
The algorithm must be deterministic.

9. No Randomness
The Selection Model must not use:
- randomness
- nondeterministic ordering
- nondeterministic tie-breaking
- nondeterministic hashing
All selection behavior must be reproducible.

10. Match Aging Rules
Match age increments only if:
- the match remains valid
- the match is not selected
Match age resets if:
- the match fires
- the match becomes invalid
- the match is rediscovered after invalidation
Match age must be stored in the match table.

11. Match Table
The engine maintains a match table containing:
- match_key
- match_age
- last_seen_tick
- dependency set
- binding environment
The match table is updated each tick.

12. Match Table Update Rules
At the start of each tick:
- matches discovered in the previous tick are carried forward
- matches not rediscovered are removed
- matches rediscovered retain their age
At the end of each tick:
- match_age increments for all matches not selected

13. Interaction with Dependency Set Model
Matches whose dependencies become invalid:
- are removed from the match table
- have their age reset
- must be rediscovered to re-enter the table

14. Interaction with Tick Model
The Selection Model runs once per tick. The Tick Model executes the selected match. If the selected match fails dependency validation or conflict detection, the Selection Model must choose a new match.

15. Interaction with Golden File Model
Golden files must record:
- match scores
- match ages
- fairness boosts
- tie-break components
- selected match
Any deviation indicates nonconformance.

16. Invalid Matches
A match is invalid if:
- its dependency set cannot be validated
- its binding environment is inconsistent
- its rule definition is invalid
Invalid matches must not be selected.

17. Extensibility
Future versions may extend the Selection Model with:
- weighted fairness
- priority decay
- deterministic batching
All extensions must preserve determinism.

End of GRISP SPEC 013 — SELECTION MODEL (v0.17 DRAFT)
