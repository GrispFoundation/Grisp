GRISP SPEC 002 — EXPRESSION AST (v0.17 DRAFT)

Status: Draft
Layer: 0 (Deterministic Core)
Depends on: Spec 001 Canonical IR, Spec 014 Dependency Set Model

Purpose:
This specification defines the canonical Expression Abstract Syntax Tree (Expression AST) used throughout GRISP. All expressions in patterns, when clauses, let bindings, and actions must be represented using this AST. The Expression AST is deterministic, fully explicit, and contains no implicit behavior. All engines must evaluate Expression ASTs identically.

1. Overview
The Expression AST is a pure functional expression language. It contains no side effects, no nondeterministic constructs, and no implicit conversions. All evaluation is deterministic and depends only on the current state, the match bindings, and pure function calls. The AST is used for:
- field access
- literal values
- arithmetic
- boolean logic
- comparisons
- conditional expressions
- function calls
- collection expressions
- structural expressions used in actions

2. Expression Kinds
Every expression has a kind field that determines its structure. The allowed kinds are:
literal
identifier
field
binary
unary
if
call
collection
list
map

No other expression kinds are permitted.

3. Literal Expressions
A literal expression represents a constant value. It consists of:
kind: literal
value: one of string, integer, boolean, float, null
Literal expressions have no dependencies.

4. Identifier Expressions
An identifier expression refers to a bound name in the rule environment. It consists of:
kind: identifier
name: the identifier string
Identifiers refer to:
- pattern bindings
- let bindings
Identifiers do not refer to fields directly. Field access must use field expressions.

5. Field Expressions
A field expression accesses a field on a bound node. It consists of:
kind: field
target: an identifier expression
field_name: the name of the field
Field expressions contribute Field dependencies in Spec 014.

6. Binary Expressions
A binary expression applies an operator to two subexpressions. It consists of:
kind: binary
op: one of + - * / % == != < <= > >= and or
left: Expression AST
right: Expression AST
Binary expressions must be evaluated left-to-right with no reordering. Division by zero is a validation error.

7. Unary Expressions
A unary expression applies a unary operator to a subexpression. It consists of:
kind: unary
op: one of not - (negation)
expr: Expression AST

8. Conditional Expressions
A conditional expression selects between two branches. It consists of:
kind: if
cond: Expression AST
then: Expression AST
else: Expression AST
The cond expression must evaluate to a boolean. Both branches must be well-typed.

9. Function Call Expressions
A function call expression invokes a function defined in the Canonical IR. It consists of:
kind: call
function_name: string
args: list of Expression AST
Function calls must reference pure or effect_deterministic functions only. Effect_nondeterministic functions are forbidden in Expression AST. Function calls contribute dependencies according to Spec 014 if the function is effect_deterministic.

10. Collection Expressions
A collection expression enumerates nodes or edges of a given type. It consists of:
kind: collection
source:
  type: node or edge
  name: type name
filter: optional Expression AST
order_by: optional list of:
  expr: Expression AST
  direction: asc or desc
limit: optional integer literal

Collection expressions have deterministic semantics:
1. Enumerate all instances of the source type.
2. Apply filter if present.
3. Sort results lexicographically by order_by expressions.
4. If no order_by is present, sort by canonical identifier ascending.
5. Apply limit if present.
6. Return the resulting list of node or edge identifiers.

Collection expressions contribute the following dependencies:
Extent(type)
Predicate(type, field) for each field referenced in filter
Ordering(type, field) for each field referenced in order_by
Field(id, id) for identity ordering

11. List Expressions
A list expression constructs a list of values. It consists of:
kind: list
items: list of Expression AST
List expressions evaluate each item left-to-right.

12. Map Expressions
A map expression constructs a mapping from string keys to values. It consists of:
kind: map
entries: list of:
  key: string
  value: Expression AST
Map expressions evaluate values left-to-right.

13. Deterministic Evaluation Rules
Expression evaluation must follow these rules:
- No short-circuit reordering beyond the semantics of and/or.
- No constant folding beyond literal-literal operations.
- No algebraic simplification.
- No implicit type conversions.
- All arithmetic uses deterministic integer or fixed-point semantics.
- All comparisons use deterministic ordering rules.

14. Type System Integration
Every expression must be type-checked before execution. The type system includes:
string
integer
boolean
float (deprecated in v0.17)
list
map
identifier
node reference
edge reference

Float is deprecated and must not be used in new manifests. Fixed-point integer arithmetic is recommended.

15. Dependency Extraction
Spec 014 defines how dependencies are extracted from Expression AST. The Expression AST must expose all field accesses, function calls, and collection structures explicitly so that dependency extraction is deterministic.

16. Validation Requirements
Engines must validate Expression ASTs before execution:
- All identifiers must resolve to known bindings.
- All field accesses must reference valid fields.
- All function calls must reference known functions.
- No effect_nondeterministic functions may appear.
- All collection expressions must specify source types explicitly.
- All order_by expressions must be valid and well-typed.

Invalid expressions must cause manifest rejection.

17. Extensibility
Future versions may extend the Expression AST with:
- additional operators
- pattern comprehensions
- deterministic aggregations
All extensions must preserve determinism and must be expressible in a way compatible with Spec 014.
