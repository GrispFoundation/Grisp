============  GRISP v0.16 — Spec 001 - CANONICAL IR  ============

Status: Draft
Layer: 0 (Deterministic Execution Core)
Depends on:
- Spec 002 Expression AST
- Spec 007 Transaction Model
- Spec 011 State Model
- Spec 013 Selection Model

1. Purpose
Canonical IR defines the deterministic execution contract for all GRISP engines. It specifies the schema for rule definitions, node type definitions, edge type definitions, function definitions, and manifests. Canonical IR contains no trust semantics, no AI constructs, and no runtime policy. It is a pure, stable, deterministic representation.

2. Manifest Structure
A manifest defines the static schema and rule set.

{
  "ir_version": "grisp-ir-v0.16",
  "manifest_id": "string",
  "manifest_version": "string",
  "node_types": [...],
  "edge_types": [...],
  "functions": [...],
  "rules": [...],
  "metadata": {},
  "custom": {}
}

3. Node Types
Node types define the schema for fact instances stored in the graph state.

{
  "name": "Task",
  "fields": {
    "id": { "type": "identifier" },
    "lifecycle": { "type": "string" },
    "priority": { "type": "integer", "default": 0 }
  },
  "constraints": [
    {
      "kind": "expression",
      "expr": { Expression AST }
    }
  ],
  "custom": {}
}

Rules:
- Node types define schema only.
- Instances are defined in Spec 011 State Model.
- Field types must be one of: string, integer, boolean, identifier, float, list, map.
- Default values apply when omitted in create actions.

4. Edge Types
Edge types define typed relationships between node instances.

{
  "name": "AssignedTo",
  "from": "Task",
  "to": "Agent",
  "multiplicity": "many_to_one",
  "custom": {}
}

Rules:
- Edge instances are defined in Spec 011 State Model.
- Multiplicity is one of: one_to_one, one_to_many, many_to_one, many_to_many.
- Engines must enforce multiplicity constraints during transaction validation.

5. Function Definitions
Functions are pure or effectful operations callable from expressions or actions.

{
  "name": "compute_score",
  "kind": "pure",
  "signature": {
    "params": [
      { "name": "task", "type": "Task" }
    ],
    "returns": { "type": "integer" }
  },
  "custom": {}
}

Rules:
- Function signatures use normalized AST, not string syntax.
- Function kinds are: pure, effect, nondeterministic.
- Pure functions must be deterministic and side-effect free.
- Nondeterministic functions may only appear in effect actions, never in expressions.

6. Rule Structure

{
  "rule_id": "AssignTask",
  "rule_version": "1.0.0",
  "when": [...],
  "let": [...],
  "then": [...],
  "metadata": {},
  "custom": {}
}

7. Match Patterns
Patterns bind facts from the graph state.

{
  "bind": "t",
  "type": "Task",
  "where": {
    "kind": "binary",
    "op": "==",
    "left": { "kind": "field", "path": ["t", "lifecycle"] },
    "right": { "kind": "literal", "literal_type": "string", "value": "pending" }
  }
}

Rules:
- All conditions use Expression AST.
- Bindings must be unique within a rule.
- Pattern evaluation is defined in Spec 007 Transaction Model.

8. Let Bindings

{
  "name": "score",
  "expr": { Expression AST }
}

Rules:
- Let bindings are evaluated after pattern matching.
- Let bindings may not modify graph state.
- Let bindings may not call effect or nondeterministic functions.

9. Actions
Actions modify graph state or call external tools. Canonical IR defines only the schema. Execution semantics are in Spec 007.

Example update action:

{
  "kind": "update",
  "target": "t",
  "assigns": {
    "lifecycle": {
      "kind": "literal",
      "literal_type": "string",
      "value": "assigned"
    }
  }
}

Allowed kinds:
- create
- update
- delete
- call
- emit

Clarify actions are defined in Spec 005 Boundary Contract.

10. Read and Write Inference
Canonical IR requires complete and correct inference of reads and writes for each rule.

10.1 Inferred Reads
A rule reads:
- all fields referenced in pattern expressions
- all fields referenced in let expressions
- all fields referenced in action expressions
- all fields of any fact bound in a pattern with no where clause
- all fields accessed via field expressions

10.2 Inferred Writes
A rule writes:
- all fields assigned in update actions
- all fields of created facts
- deletion of a fact counts as writing all its fields
- creation or deletion of edges counts as writing the edge type

10.3 Formal Algorithm
The following algorithm is normative:

Step 1: Initialize empty sets inferred_reads and inferred_writes.
Step 2: Walk all expressions in when, let, then.
Step 3: For each field access expression, add (binding, field) to inferred_reads.
Step 4: For each update action, add (binding, field) to inferred_writes.
Step 5: For each create action, add all fields of the node type to inferred_writes.
Step 6: For each delete action, add all fields of the node type to inferred_writes.
Step 7: For each edge create or delete, add the edge type to inferred_writes.
Step 8: Output both sets.

11. Canonical Serialization
Canonical IR objects must serialize to canonical JSON:
- sorted keys
- UTF-8
- no whitespace beyond single spaces
- no trailing commas
- deterministic number formatting

Graph hashing is defined in Spec 011 State Model.

12. Validation Rules
A manifest is valid if:
- all node types have unique names
- all edge types reference valid node types
- all functions have valid signatures
- all rules reference valid types and bindings
- inferred_reads and inferred_writes are computable
- no nondeterministic functions appear in expressions
- all actions reference valid bindings

13. Summary
Canonical IR v0.16 defines:
- normalized schema for rule definitions
- normalized schema for node and edge types
- normalized function signatures
- deterministic read and write inference
- deterministic serialization
- no trust, no AI, no runtime policy

It is the stable execution contract for all GRISP engines.
