Hier zijn de specificaties van v0.21 tot en met v0.28, zoals ze in de conversatie zijn ontstaan. Voor de volledigheid heb ik v0.20 als basis meegenomen en v0.29 als eindpunt. Elke versie toont de evolutie van een losse verzameling ideeën naar een vrijwel voltooide kernel.

---

## v0.20 – Basisarchitectuur (referentie)

Deze versie legt de fundamentele principes vast: determinisme, frozen discovery, dependency validation als enige correctheidsmechanisme, één commit per tick, identifier model, versietellers, enz. Grote gaten: geen expliciete string‑/map‑semantiek, geen aggregatie‑dependency‑regels, geen formele no‑op semantiek, edge existence ontbreekt, function termination onbeslisbaar, etc.

---

## v0.21 – Eerste delta (alleen wijzigingen)

Dit was een patch bovenop v0.20. De belangrijkste toevoegingen:

- **String semantics**: UTF‑8, code point ordering, geen normalisatie.
- **Map semantics**: keys strings, canonical serialisation met gesorteerde keys.
- **Rule ID stability**: expliciete `rule_id` in IR, compiler mag niet genereren.
- **Declared reads**: conservative superset, over‑approximation toegestaan.
- **Aggregate dependencies**: `count` → `Extent`, `sum` → `Extent`+`Predicate`, etc.
- **No‑op updates**: als nieuwe waarde gelijk aan oude, dan geen versieverhoging.
- **Staged transaction validation**: pre‑commit validatie van writes.
- **Predicate/ordering version semantics**: expliciete definitie wanneer increment.
- **Edge existence model**: `EdgeExistence` dependency en `existence_version` per edge.

v0.21 was nog steeds een delta‑document; geen complete herschrijving.

---

## v0.22 – Volledige herschrijving

Eerste **self‑contained** specificatie. Geen delta meer. Oplossingen:

- String escaping nog niet, maar wel Unicode.
- Map equality gedefinieerd.
- Aggregate dependency regel formeel: moet membership, ordering en values afdekken.
- Match age recursief gedefinieerd: `age = previous_age + 1` als match_key nog bestond.
- Initial state versies: `existence_version=1`, `field_versions=1`.
- Edge `existence_version` nu correct: `CreateEdge` zet op `1` (niet `2`).
- Version increment tabel uitgebreid.

**Tekortkomingen v0.22**: type names mochten nog `:`, fixed‑point deling onduidelijk, match‑key serialisatie ambigu, duplicate map keys niet verboden, maps orderable? nee, maar niet expliciet.

---

## v0.23 – Verfijning

Grootste verbeteringen:

- **Edge field dependencies**: gesplitst in `EdgePredicate` en `EdgeOrdering`, los van `EdgeType`.
- **Tijdelijke handles** voor nodes/edges die pas tijdens commit een ID krijgen.
- **Map equality** en **recursieve canonicalisatie**.
- **Identifier syntax** beperkt tot `[A-Za-z0-9_][A-Za-z0-9_:-]*`.
- **Create‑node + delete‑node in zelfde transactie** expliciet ongeldig.
- **Termination** nu beslisbaar: recursie en loops verboden.
- Dependency extractie tabel uitgebreid (count, sum, min, sort, adjacency, etc.).

v0.23 loste de meeste architectuurproblemen op.

---

## v0.24 – Freeze candidate

Nieuwe precisies:

- **Canonieke serialisatie** van strings met escaping (`\n`, `\r`, `\t`, `\uXXXX`).
- **Compound equality** recursief voor lijsten en mappen.
- **Verplichte velden** (geen null).
- **Handle → identifier mapping** deterministisch door volgorde van acties.
- **DeleteNode + expliciete DeleteEdge** conflict opgelost via merging.
- **Dependency extraction** nu normatief met voorbeeldtabel.

v0.24 scoorde 9.7/10.

---

## v0.25 – Laatste grote gaten

Deze versie (niet volledig getoond in chat, maar afgeleid van feedback) voegde toe:

- **Fixed‑point deling** correcte formule: `(v_d * 10^s_r) // v_r`, result scale = `s_d`.
- **Type names geen colon meer** (voorkomt ambiguïteit met identifier).
- **Match key** nu canonical serialisatie van een object, niet simpele concatenatie.
- **Duplicate map keys** verboden.
- **Maps zijn niet orderable** – sorteeroepraties op lijsten van maps zijn ongeldig.

---

## v0.26 – Type‑parameters

Cruciale toevoeging:

- **Generieke types**: `List<T>`, `Map<K,V>` met `K` = `String`.
- **Orderability** formeel gedefinieerd: `List<T>` orderable **iff** `T` orderable; `Map` nooit.
- **Binding names** en **`rule_id`** grammatica vastgelegd (ASCII, zelfde als type name).
- **Fatal conformance error** gedefinieerd: halteert executie, golden file registreert error.

---

## v0.27 – Randgevallen dicht

- **Division by zero** is runtime fatal error, geen IR‑validatie.
- **Fixed‑point vergelijking zonder overflow** (gebruik arbitrary precision of veilig algoritme).
- **Canonieke ordening** overal UTF‑8 bytewise (consistent met serialisatie).
- **Match‑key record** serialisatie formeel via SPEC 018 (geen “JSON‑like”).
- **Event payload dependencies** worden altijd geëxtraheerd, ook als transactie later wordt afgekeurd.
- **DeleteNode + CreateEdge** automatische verwijdering toegestaan als edge net is aangemaakt.
- **match_age** expliciete regel: alleen vorige telt; verdwenen = nieuwe match (age=0).

---

## v0.28 – Laatste polijstslag

De versie die net voor v0.29 verscheen. Belangrijkste punten:

- `ordering_version` hernoemd naar `ordering_dependency_version` (semantiek is “iets veranderde dat ordering kan beïnvloeden”, niet “sortering veranderde”).
- **Fatal error** nu volledig beschreven in SPEC 000.
- **Record serialisatie** voor match key expliciet als map (SPEC 018).
- **Rule ID** en **binding name** grammatica expliciet in SPEC 005 en SPEC 009.
- **Canonieke ordering** (UTF‑8 bytewise) consequent toegepast op type names, binding names, rule IDs, veldnamen.
- **Conformance note**: dependency extraction compleetheid is testbaar via observatie; over‑approximatie toegestaan.

---

## v0.29 – Freeze candidate (volledige specificatie)

Deze is hierboven in het vorige antwoord gegeven. Het is de eerste versie die geen openstaande architectuurproblemen meer heeft. Alle punten uit eerdere reviews zijn verwerkt.

---

Als je de **volledige tekst** van elke versie (v0.21–v0.28) wilt zien zoals die in de chat gegenereerd zijn, kan ik die als losse berichten sturen. Maar vanwege de lengte heb ik hier de essentie per versie samengevat. De grootste sprongen waren:

- **v0.20 → v0.21**: introductie van edge existence, aggregated dependencies, no‑op.
- **v0.21 → v0.22**: herschrijving tot zelfstandige spec.
- **v0.22 → v0.23**: edge predicate/ordering, tijdelijke handles.
- **v0.23 → v0.24**: canonical serialisatie, string escaping, compound equality.
- **v0.24 → v0.25**: fixed‑point deling, type names zonder dubbele punt, match‑key object.
- **v0.25 → v0.26**: generics, orderability, fatal error definitie.
- **v0.26 → v0.27**: division by zero runtime, veilige fixed‑point vergelijking, event dependency extractie altijd.
- **v0.27 → v0.28**: hernoeming `ordering_dependency_version`, formele record serialisatie.
- **v0.28 → v0.29**: alle resterende randgevallen dicht, freeze candidate.

Wil je dat ik één van deze versies als **volledig document** (dus de gehele SPEC 000 t/m 020) uitschrijf? Dan kan ik bijvoorbeeld v0.22, v0.25 of v0.28 compleet genereren.
