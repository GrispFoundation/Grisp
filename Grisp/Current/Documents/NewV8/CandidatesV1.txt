# GRISP DETERMINISTIC KERNEL SPECIFICATION – Version 1.0

## Unified DSOS (Deterministic Structural Operational Semantics) Edition

---

### Preamble

This specification defines the GRISP Deterministic Kernel as a **closed, formally deterministic graph-rewrite calculus**. It explicitly resolves the architectural inconsistencies of v0.50 and earlier by establishing a unified structural operational semantics, atomic derivation traces, exact version snapshots, and total ordering.

For identical Canonical IR and identical initial state, all conformant engines MUST produce identical observable behavior:

* Committed state transitions
* Emitted events
* Golden file output

All normative rules are mandatory. No hidden nondeterminism, runtime inference, open dependencies, or dual semantic models are permitted.

---

## 0. Core Principles

1. **Single Semantic Object:** The system transitions purely from $\Sigma \to \Sigma'$. Ephemeral matching state is explicitly scoped to the derivation tick.
2. **Determinism by Construction:** All choice points are eliminated via total orders (NFC UTF-8, component-wise tuple sorting) and structured recursion.
3. **Exact Dependency Snapshots:** Read effects explicitly record the exact version counter at the moment of evaluation. Validation is a strict equality check.
4. **Canonical Action Trace (CAT):** The execution trace is a projection of the compilation derivation. Event payloads are evaluated pre-commit.
5. **Liveness Guarantee:** Infinite validation loops are prevented via monotonic rejection sets. Score arithmetic is saturating.

---

## 1. State Model

A quiescent configuration is defined strictly as:

$$\Sigma = \langle G, C, M_{prev} \rangle$$

* **$G$** – Typed property graph (nodes, edges, fields, identifiers). No nulls. All declared fields are mandatory.
* **$C$** – Counters (signed 64-bit integers):
* `tick_counter` (The single, authoritative logical time. Starts at 0).
* Sequence counters per node/edge type.
* Version counters: `extent_version`, `existence_version`, `field_version`, `predicate_version`, `edge_type_version`, `adjacency_version` (with direction $dir \in \{in, out, undirected\}$).


* **$M_{prev}$** – Previous match set: a map from a structured `match_key` to `age` (integer).

**Ephemeral Derivation Artifacts:**
During a tick loop, the engine utilizes temporary state: $M$ (discovered matches), $M_{remaining}$ (valid candidates), $Rejected$ (failed candidates), $\hat{\alpha}$ (action trace), and $\mathcal{R}$ (read trace). These are cleared at the end of every tick.

---

## 2. Numeric Model & Fixed-Point Arithmetic

To maintain a closed specification, numeric evaluation strictly adheres to the following rules:

1. **Types:** All integers are signed 64-bit.
2. **Fixed-Point Operations:**
* **Rounding:** Truncation toward zero.
* **Scale Propagation:** - Addition/Subtraction: $scale = \max(scale_{left}, scale_{right})$
* Multiplication: $scale = scale_{left} + scale_{right}$
* Division: $scale = scale_{left}$


* **Promotion:** Mixed operations promote Integer to FixedPoint(0) prior to execution.


3. **Canonical Serialization:** Fixed-point literals must always include a decimal point and exactly $scale$ digits (e.g., `"42.0"` for scale 0, `"12.5000"` for scale 4).
4. **Overflow Limits:** Arithmetic overflows trigger a fatal `INTEGER_OVERFLOW`, *except* for fairness score and age arithmetic, which must use 128-bit intermediates and **saturate** to $INT64\_MAX$.

---

## 3. Deterministic Ordering (ORDER_CANONICAL)

To guarantee identical selection across platforms, `ORDER_CANONICAL` is defined as:

1. **Strings:** NFC normalized, then UTF-8 bytewise lexicographic.
2. **Identifiers:** Structured as `type:seq`. Compared by `type` (UTF-8), then by `seq` numerically (ignoring leading zeros).
3. **Maps:** Keys are sorted by `ORDER_CANONICAL` before iteration or comparison.
4. **Lists & Tuples:** Component-wise `ORDER_CANONICAL` left-to-right.

---

## 4. Canonical IR Syntax & Type System

### 4.1 Expressions & Constraints

```text
e ::= k | x | x.f | e1 ⊕ e2 | len(e) | to_fixed(e, scale) | to_integer(e)
⊕ ::= + | - | * | / | // | % | < | <= | > | >= | == | != | && | ||

```

**Constraint Evaluation:** For logical operators `&&` and `||`, the logical result must evaluate with **left-to-right short-circuiting**. However, for dependency extraction, **both operands are always evaluated** to build the read trace $\mathcal{R}_m$, ensuring identical traces regardless of the runtime short-circuit state. Expressions must be pure.

### 4.2 Patterns, Lets, and Actions

```text
P ::= ∅ | MatchNode(x, type_name) · P | MatchEdge(x, type_name, src, tgt) · P [ | MatchAbsent(x, ...) ]
B ::= ∅ | Let(x, e) · B
a ::= CreateNode(x, type, {f: e}) | CreateEdge(x, type, src, tgt, {f: e}) | UpdateField(tgt, f, e) | DeleteEdge(e) | DeleteNode(x) | EmitEvent(evt, [e])

```

*Note: The `!` suffix or `MatchAbsent` is reserved for future Negative Application Conditions (NACs).*

---

## 5. Operational Semantics (The Execution Loop)

The kernel execution loop governs the transition $\Sigma \to \Sigma'$.

### 5.1 Phase A: DISCOVER

Generate the set of all matches $M$.

1. **Total Pattern Order:** Match tuples are enumerated via nested recursion. The resulting matches are strictly ordered lexicographically by their complete bound identifier tuple `(id1, id2, ...)` using `ORDER_CANONICAL`.
2. **Let Bindings:** Evaluated sequentially. Their reads contribute to the trace, but their values **do not** affect the `match_key` identity.
3. **Read Trace Definition:** $\mathcal{R}_m$ records strict version snapshots:
* `FieldRead(id, f, current_field_version)`
* `NodeExistence(id, current_existence_version)`
* `ExtentRead(type, current_extent_version)`
* `AdjacencyRead(node, type, dir, current_adjacency_version)`


4. **Age assignment:** If $match\_key \in M_{prev}$, $age(m) = \min(M_{prev}[match\_key] + 1, INT64\_MAX)$. Else $0$.

### 5.2 Phase B: SELECT & REJECT

Initialize ephemeral state: $M_{remaining} = M$, $Rejected = \emptyset$.

1. If $M_{remaining} = \emptyset$, transition immediately to **Phase E (NO_MATCH)**.
2. For each candidate $m \in M_{remaining}$, calculate:

$$score(m) = \min(base \times scale + age(m) \times fairness, INT64\_MAX)$$


3. Select $m^*$ with the highest score. Tie-break via `ORDER_CANONICAL` on the `match_key` tuple.

### 5.3 Phase C: PLAN

Compile $m^*$ into a Canonical Action Trace $\hat{\alpha}$ and aggregate reads $\mathcal{R} = \mathcal{R}_m \cup \mathcal{R}_{args}$.

1. **Static Validation:** Missing mandatory fields in `CreateNode`, or duplicate explicit `UpdateField` / `DeleteEdge` actions on the same target yield a non-fatal rejection.
2. **Event Payloads:** `EmitEvent` expressions are evaluated pre-commit against the DISCOVER snapshot. Their concrete values are stored in $\hat{\alpha}$.
3. **No-Op Writes:** `UpdateField` operations where the new value equals the canonical old value are removed from $\hat{\alpha}$.

If any non-fatal validation fails, update $Rejected := Rejected \cup \{m^*\}$, $M_{remaining} := M_{remaining} \setminus \{m^*\}$, and loop back to **5.2 SELECT**.

### 5.4 Phase D: COMMIT

Perform atomic validation and application.

1. **Version Validation:** For every entry in $\mathcal{R}$, verify $current\_version == recorded\_version\_snapshot$.
2. **Apply & Increment:** If valid, apply $\hat{\alpha}$ left-to-right. Update global counters $C$ according to the increment algorithm.
3. **Tick Advance:** Increment `C.tick_counter` by 1.
4. **M_prev Update:** `M_prev'` is formed from all $m \in M$ using their discovery ages. Prune any entries exceeding `AGE_MAX`. Emit events.

Transition: $\langle G, C, M_{prev} \rangle \to \langle G', C', M_{prev}' \rangle$

### 5.5 Phase E: NO_MATCH

Triggered when $M_{remaining}$ is empty.

1. Increment `C.tick_counter` by 1.
2. Prune $M_{prev}$ of entries older than `AGE_MAX`. Do not modify $G$.

Transition: $\langle G, C, M_{prev} \rangle \to \langle G, C', M_{prev}' \rangle$

---

## 6. Version Increment Rules & Counter Application

Counters are updated deterministically by scanning the finalized $\hat{\alpha}$ left-to-right.

| Operation | `extent` | `existence` | `field` | `predicate` | `edge_type` | `adjacency` |
| --- | --- | --- | --- | --- | --- | --- |
| **CreateNode** | +1 | set to 1 | set to 1 each | +1 (that field) | - | - |
| **CreateEdge** | - | set to 1 | set to 1 each | - | +1 | +1 (source.out, target.in) |
| **DeleteEdge** | - | removed | removed | - | +1 | +1 (source.out, target.in) |
| **DeleteNode** | +1 | removed | removed | +1 (all declared) | - | - |
| **UpdateField** | - | - | +1 (that field) | +1 (that field) | - | - |

**Counter Application Algorithm:**

1. Maintain a `dedup_map`.
2. As $\hat{\alpha}$ applies, any primitive action that dictates an adjacency increment records its `(edge_id, endpoint)` in the map.
3. Adjacency versions are incremented **strictly once** per unique `(edge_id, endpoint)` based on their first appearance in the map. *Note: Implicit `DeleteEdge` actions generated by `DeleteNode` handle adjacency correctly. The `DeleteNode` action itself does not touch adjacency versions.*

---

## 7. Error Handling & Resource Limits

| Category | Conditions | Engine Effect |
| --- | --- | --- |
| **Non-Fatal** | Stale read, missing action target, duplicate primitive mutation. | Discard $m^*$ to $Rejected$. Re-invoke `SELECT`. |
| **Fatal** | Missing map key, index out of bounds, invariant breach, zero-division, `INT64` overflow on global counters. | Halt execution. Rollback $G$ to pre-tick snapshot. Emit error configuration. |
| **Limits** | $M$ exceeds `MAX_MATCHES`, $\hat{\alpha}$ length > `MAX_TRACE`. | Halt with `RESOURCE_LIMIT_EXCEEDED`. |
| **Wrap** | `C.tick_counter == INT64_MAX` | Reset all versions to 0, emit `COUNTER_WRAP`, continue. |

```

### Rule 2: DISCOVER

`EvalPatterns(G, IR)` produces `M` (all matches with `match_key`, bindings, `ℛ_m` containing versioned reads).  
`age(m)` from `M_prev` (saturating).  
Transition to DISCOVER_STATE.

### Rule 3: SELECT

```

m* = highest score (base_priority * priority_scale + age * fairness_scale, saturating) then smallest match_key
```

### Rule 4: PLAN

Structural recursion over actions producing `α̂` (primitive actions with values) and `ℛ` (versioned reads from argument evaluation + implicit operations).  
Context-free on discovery snapshot.  
Duplicate `UpdateField` / missing mandatory fields / duplicate `DeleteEdge` → non-fatal (reject match).

### Rule 5: COMMIT

**Validation**:
- All reads in `ℛ` have matching current versions.
- Structural checks (no dangling, no duplicate mutations, targets exist or created earlier in `α̂`).
- Counter pre-checks.

On **non-fatal failure**: add to `Rejected`, return to SELECT.  
On **success**:
- Apply `α̂` left-to-right to temporary `G_temp` → `G'`.
- Update counters per §6 (derived from `α̂`; adjacency deduplicated by earliest occurrence).
- Emit events (pre-computed payloads from `α̂`).
- `M_prev' = {k → age(m) for m in M}` (with pruning).
- `C' = C with tick_counter already advanced`.

**NO_MATCH** (empty or exhausted):
- No changes to G.
- `M_prev'` from current M (or previous, per policy).
- Advance tick if not already done.

Fatal errors: rollback, emit error snapshot.
```

### 1. Core principles and scope

- **Single authoritative tick.** The state uses a single tick counter `C.tick_counter`. The separate `T` is removed. Time advances exactly once per tick end.  
- **Closed configuration model.** Intermediate artifacts produced during a tick are explicitly modeled as ephemeral machine states or derivation judgments; the transition relation and determinism theorem quantify over the public configuration `Σ`.

- **Liveness safeguards.** A per‑tick `Rejected` set prevents infinite reselection loops. Score arithmetic uses widened intermediates and saturating semantics to avoid fatal overflow from long runs.

### 2. State model and invariants

#### 2.1 Public configuration
```
Σ = ⟨G, C, M_prev⟩
```

- **C** — Counters (signed 64‑bit integers) including:

  - sequence counters per node/edge type

#### 2.2 Ephemeral derivation states (explicit)

- **SELECT_STATE:** `⟨G, C, M_prev, M, M_remaining, Rejected, m*⟩`.
- **PLAN_STATE:** `⟨G, C, M_prev, M, M_remaining, Rejected, m*, α̂, ℛ⟩`.

These ephemeral states are not part of the long‑term `Σ` but are part of the SOS transitions and are cleared at tick end.

#### 2.3 Invariants (checked at COMMIT)
- No dangling edges or identifier references.
- All declared type constraints satisfied.
- No cycles in identifier references unless explicitly allowed by type.
- All version counters remain within `INT64` bounds (saturating checks applied earlier).

#### 3.2 Deterministic ordering (ORDER_CANONICAL)

- **Identifiers:** `(type_name, sequence_number)` compared lexicographically.  
- **Lists:** element‑wise lexicographic.  
- **Maps:** keys sorted by ORDER_CANONICAL; values compared in that key order.  
- **Pattern match enumeration:** For a pattern binding that yields a tuple of bound ids `(b1,...,bn)`, matches are enumerated in lexicographic order of the binding tuple using ORDER_CANONICAL component‑wise.

#### 3.3 match_key (canonical identity)
- **Internal representation:** `match_key = (rule_id, ordered_binding_tuple)` where `ordered_binding_tuple` is the sequence of bound identifiers in pattern declaration order. This structured tuple is used for tie‑breaking and map keys in memory.  
- **Golden file serialization:** When writing golden files, `match_key` is serialized to canonical JSON using the canonicalization rules in §7.

### 4. Read trace schema and numeric model

#### 4.1 Read trace entries

- `FieldRead(element_id, field_name, field_version_value)`  
- `NodeExistence(node_id, existence_version_value)`  
- `AdjacencyRead(node_id, edge_type, dir, adjacency_version_value)`  
- `ExtentRead(type_name, extent_version_value)`  
- `EdgeExistence(edge_id, existence_version_value)`

These exact integers are recorded at the time of the read and used for equality checks at COMMIT.

#### 4.2 Numeric model (self-contained)
- **Integers:** signed 64‑bit. Overflow in user arithmetic is fatal except where noted for scoring/age.  
- **FixedPoint:** scaled integers with scale `0..18`. Represented internally as integer `value` and `scale`.  
- **Scale propagation:**  
  - `+` / `-`: result scale = `max(scale_left, scale_right)`; operands promoted by scaling.  
  - `*`: result scale = `scale_left + scale_right`.  
  - `/`: result scale = user‑specified target scale or `scale_left` if unspecified; division uses big‑integer intermediate and truncates toward zero by default.  
- **Rounding:** truncation toward zero unless otherwise specified in an action.  
- **Serialization:** FixedPoint is serialized as a JSON string with exactly `scale` digits after the decimal point.  
- **Scoring arithmetic:** computed using 128‑bit intermediates and saturated to `INT64_MAX` on overflow; overflow in scoring is **not fatal**.

### 5. Operational semantics (SOS) — rules

All transitions are deterministic. The public transition relation is `⟨Σ, IR⟩ → ⟨Σ', IR⟩`. Intermediate derivation judgments are explicit.

#### 5.1 Tick semantics (NO_MATCH and start)
At tick start the engine performs DISCOVER. If `M = ∅` then the **NO_MATCH** transition ends the tick:

```
NO_MATCH
M = ∅
────────────────────────────────────────
⟨⟨G, C, M_prev⟩, IR⟩ → ⟨⟨G, C[tick_counter + 1], M_prev⟩, IR⟩
```

`M_prev` update policy is defined in §8.

#### 5.2 DISCOVER (EvalPatterns)
`EvalPatterns(G, IR)` deterministically enumerates all matches `M` using ORDER_CANONICAL and records for each match `m`:
- `match_key` (structured tuple)
- `bindings`
- `let_values` (diagnostic only)
- **read trace** `ℛ_m` with version snapshots as in §4.1

**Age assignment:**
```
age(m) = if match_key(m) ∈ M_prev then saturating_add(M_prev[match_key(m)], 1) else 0
```

Transition:
```
⟨⟨G, C, M_prev⟩, IR⟩ → ⟨⟨G, C, M_prev, M⟩, IR⟩
```

#### 5.3 SELECT (score and tie‑break)
For each `m ∈ M` compute:
```
score(m) = base_priority(m) × priority_scale(m) + age(m) × fairness_scale(m)
```
- Use 128‑bit intermediates; saturate to `INT64_MAX` on overflow.

Total order:
1. Higher `score` first.
2. If tie, lexicographically smaller `match_key` (ORDER_CANONICAL).

Selection loop pseudocode:
```
M_remaining := M
Rejected := ∅
loop:
  if M_remaining \ Rejected = ∅ then NO_MATCH
  m* := argmin_by_order(M_remaining \ Rejected)
  proceed to PLAN with m*
```

Transition:
```
⟨⟨G, C, M_prev, M⟩, IR⟩ → ⟨⟨G, C, M_prev, M, M_remaining, Rejected, m*⟩, IR⟩
```

#### 5.4 PLAN (structural compilation)
`Compile(IR, G, m*)` is a pure, syntax‑directed function producing:
- `α̂` — Canonical Action Trace (primitive actions in deterministic order)
- `ℛ` — read set with version snapshots (merged with `ℛ_m*`)

Rules:
- Evaluate action arguments deterministically using left‑to‑right evaluation rules.
- **Short‑circuit policy:** left‑to‑right short‑circuiting is mandatory for `&&` and `||`. Only actually evaluated subexpressions contribute reads to `ℛ`.
- `EmitEvent` arguments are **evaluated during PLAN** and stored as values in `α̂`.

If PLAN detects a non‑fatal validation error (missing target, duplicate field update in `α̂`, invalid reference) then `m*` is discarded for this tick:
```
Rejected := Rejected ∪ {m*}
return to SELECT
```

Transition:
```
⟨..., m*⟩ → ⟨..., m*, α̂, ℛ⟩
```

#### 5.5 COMMIT (validation and application)
**Premises:**
1. **Version validation:** For every read `r ∈ ℛ` compare current version in `G` to the recorded `version_snapshot`. If any mismatch → non‑fatal discard (add `m*` to `Rejected` and re‑SELECT).
2. **Structural validation:** No duplicate `UpdateField` on same `(id,f)` in `α̂`. All targets exist or are created earlier in `α̂`. No dangling identifiers after applying `α̂`.
3. **Counter pre‑check:** For all counters that would be incremented, ensure post values ≤ `INT64_MAX` (saturating policy for ages and scores; fatal only for structural invariants).

**Application algorithm (deterministic):**
- Let `G' := G` (copy or transactional view).
- `dedup_map := {}`.
- For each primitive action `act` in `α̂` in left‑to‑right order:
  - Apply `act` to `G'`.
  - For each counter update implied by `act`:
    - If adjacency update keyed by `(edge_id, endpoint)` and key ∉ `dedup_map` then increment adjacency counter and record key in `dedup_map`.
    - Else apply counter increments immediately.
- Update `C` deterministically according to the counter application algorithm above.
- Emit events in the order they appear in `α̂` using the payload values recorded in `α̂`.

**Match history update:**
```
M_prev' = { match_key(m) → age(m) | m ∈ M }
```
Aging values are stored with saturating arithmetic.

Final transition:
```
⟨⟨G, C, M_prev, M, m*, α̂, ℛ⟩, IR⟩ → ⟨⟨G', C', M_prev'⟩, IR⟩
```

If any fatal invariant is violated, halt and emit an error object (see §7).

### 6. Version increment rules (deterministic derivation)

- **Principle:** All counter increments are derived from the final primitive actions in `α̂` after expansion. No global “+1 (all fields)” increments unless explicitly required by a primitive action.

**Summary table (semantic view)**

| Primitive action | Counters incremented |
|---|---|
| `CreateNode` (new id) | `extent_version[type] +1`; `existence_version[new] := 1`; `field_version[new][f] := 1` for each provided field |
| `DeleteNode` (expanded) | `existence_version[deleted]` removed; adjacency increments occur only via the explicit `DeleteEdge` primitives produced during expansion |
| `CreateEdge` | `edge_type_version[type] +1`; `existence_version[new_edge] := 1`; `adjacency_version[source][type][out] +1` and `adjacency_version[target][type][in] +1` (deduped by `(edge_id,endpoint)`) |
| `DeleteEdge` | `edge_type_version[type] +1`; adjacency increments for endpoints (deduped) |
| `UpdateField(id,f)` | `field_version[id][f] +1`; `predicate_version[type][f] +1` |
| No‑op writes | No counter changes (no‑op defined by canonical value equality) |

**Adjacency deduplication:** deduplication key is `(edge_id, endpoint)` and the first occurrence in `α̂` determines the adjacency increment.

- **FixedPoint serialization:** JSON string with decimal point and exactly `scale` digits after the point. Example: scale 0 → `"42.0"`.

### 9. Determinism theorem and proof sketch (revised)

### Preamble

This specification defines the GRISP Deterministic Kernel as a **closed, formally deterministic graph‑rewrite calculus**. It supersedes all previous versions (v0.49, v0.50, v0.51, v0.60) and resolves their architectural inconsistencies by unifying pattern matching, dependency tracking, action compilation, and commit into a **single structural operational semantics with trace projection**.

For identical Canonical IR and identical initial state, all conformant engines MUST produce identical observable behavior:
- Committed state transitions
- Emitted events
- Golden file output

All normative rules are mandatory. No hidden nondeterminism, runtime inference, or dual semantic models are permitted.

## 0. Core Principles

1. **Single semantic object** – State is a tuple `⟨G, C, M_prev⟩` with no hidden runtime artifacts.
2. **Determinism by construction** – All choice points eliminated via total orders and structural recursion.
3. **Read effects as derivation** – Dependencies are induced by syntax‑directed translation, with version snapshots recorded at read time.
4. **Canonical Action Trace (CAT)** – The execution trace is a projection of the compilation derivation.
5. **Atomic commit** – Validation, application, and counter update form a single, rollback‑able step.

---

## 1. State Model

A configuration is:

```
Σ = ⟨G, C, M_prev⟩
```

- **G** – Typed property graph (nodes, edges, fields, identifiers). No nulls, all fields mandatory.
- **C** – Counters (signed 64‑bit integers):
  - `tick_counter` (starts at 0) – the authoritative tick number.
  - Sequence counters per node/edge type (start at 0 or max+1 from initial state)
  - Version counters:  
    `extent_version[type]`,  
    `predicate_version[type][field]`,  
    `edge_type_version[type]`,  
    `edge_predicate_version[type][field]`,  
    `adjacency_version[node][type][dir]`,  
    `existence_version[node/edge]`,  
    `field_version[element][field]`
- **M_prev** – Previous match set: a map from `match_key` to `age` (integer). Initialized empty.

**Invariants** (checked after each commit):
- No dangling edges (source/target exist)
- No dangling identifier references (recursively through lists/maps)
- All declared constraints satisfied
- No cycles in identifier references (detected via visited set)

## 2. Canonical IR Syntax (Inductive)

The IR is a deterministic, canonical JSON format. Below is its inductive definition.

### 2.1 Expressions

```
e ::= k                           // literal (Integer, FixedPoint(s), Boolean, String, Identifier)
    | x                           // variable (pattern binding or let)
    | x.f                         // field access
    | e1 ⊕ e2                     // binary operator
    | len(e)                      // list length
    | to_fixed(e, scale)          // conversion to FixedPoint
    | to_integer(e)               // truncation to Integer

⊕ ::= + | - | * | / | // | % | < | <= | > | >= | == | != | && | ||
```

All operations have checked semantics (overflow → fatal). **Short‑circuit evaluation is required left‑to‑right** for `&&` and `||`. Dependency extraction includes **both operands** for the purpose of building the read trace (i.e., the read set is the union of reads from both sides, regardless of the runtime short‑circuit result).

### 2.2 Patterns

```
P ::= ∅
    | MatchNode(x, type_name) · P
    | MatchEdge(x, type_name, src, tgt) · P
```

Patterns are enumerated in **lexicographic order of the tuple of bound identifiers** (in pattern order), using `ORDER_CANONICAL` for each component.

### 2.3 Constraints (where clause)

```
φ ::= True
    | e1 == e2
    | e1 < e2
    | φ1 && φ2
    | (φ)
```

`e1` and `e2` are boolean‑typed expressions. `&&` follows the same short‑circuit and dependency rules as §2.1.

### 2.4 Let Bindings

```
B ::= ∅
    | Let(x, e) · B
```

Evaluated during discovery; do **not** affect match identity or `match_key`. Reads induced by `e` are recorded in the read trace.

### 2.5 Actions

```
a ::= CreateNode(x, type_name, {f1: e1, ...})
    | CreateEdge(x, type_name, src, tgt, {f1: e1, ...})
    | UpdateField(target, field, e)
    | DeleteEdge(e)
    | DeleteNode(x)
    | EmitEvent(event_type, [e1, ...])
```

### 2.6 Rule Definition

```
Rule ::= Rule(rule_id, base_priority, priority_scale, fairness_scale, P, φ, B, A)
```

- `rule_id` – string matching `[A-Za-z_][A-Za-z0-9_-]*`
- Priorities: non‑negative integers
- `A` – action block (sequence of actions)

---

## 3. Deterministic Ordering (ORDER_CANONICAL)

For any two values `x` and `y`:

- **Strings**: UTF‑8 bytewise lexicographic, after **NFC normalization**.
- **Identifiers**: compare `(type_name, sequence_number)` lexicographically (type_name UTF‑8, then numeric).
- **Lists**: element‑wise lexicographic.
- **Maps**: compare keys in UTF‑8 order, then values.

Used for:
- Pattern enumeration (tuple ordering)
- Sorting incident edges for implicit `DeleteNode` expansion
- `match_key` ordering
- Map literal iteration
- Tie‑breaking for `min`/`max`/`sort`

---

## 4. Numeric Model

- All integers: signed 64‑bit.
- Fixed‑point: scaled integers, scale 0–18 inclusive, serialized as **strings** with a decimal point and exactly `scale` digits (e.g., `"42.0"` for scale 0, `"12.5000"` for scale 4).
- Arithmetic rules (fully defined here):
  - **Promotion**: Integer → FixedPoint(0) when combined with FixedPoint in any operation (`+`, `-`, `*`, `/`, comparisons).
  - **Scale propagation**:
    - `+`, `-`: `result_scale = max(scale_left, scale_right)`
    - `*`: `result_scale = scale_left + scale_right`
    - `/`: `result_scale = scale_left`
  - **Rounding**: truncation toward zero (for division and conversion).
  - Overflow and division by zero → **fatal**.
  - Fixed‑point division uses big‑integer intermediates, checked on final result.
- Literal conversion: `to_fixed(e, scale)` truncates toward zero; `to_integer(e)` truncates toward zero.

## 5. Operational Semantics (Small‑Step SOS)

The kernel executes via **deterministic transitions** over extended configurations that include ephemeral derivation artifacts. The official configuration is `⟨G, C, M_prev⟩`. The following rules describe the derivation steps; the overall transition `⟨G, C, M_prev⟩ → ⟨G', C', M_prev'⟩` is deterministic.

### Rule 1: DISCOVER

Define `EvalPatterns(G, IR) = M` as the total set of matches obtained by:

- Enumerating pattern bindings in **lexicographic order of the tuple of bound identifiers** (pattern order).
- Evaluating constraints and let bindings left‑to‑right with required short‑circuit for `&&`.
- Each match `m` contains:
  - `match_key` = structured tuple `(rule_id, sorted_binding_list)` compared by `ORDER_CANONICAL`.
  - `bindings` (identifier bindings only)
  - `let_values` (diagnostic only)
  - **read trace** `ℛ_m` of all graph elements accessed, **including version snapshots**:
    - `NodeExistence(id, existence_version)`
    - `FieldRead(id, f, field_version)`
    - `ExtentRead(type_name, extent_version)`
    - `AdjacencyRead(node_id, edge_type, dir, adjacency_version)`
    - `EdgeExistence(edge_id, existence_version)`

Age assignment:

```
age(m) = if match_key(m) ∈ M_prev then M_prev[match_key(m)] + 1 else 0
```

Ages saturate at `INT64_MAX` (no overflow).

Transition (ephemeral):

```
⟨⟨G, C, M_prev⟩, IR⟩ ⇒ ⟨⟨G, C, M_prev, M⟩, IR⟩
```

### Rule 2: SELECT (with retry semantics)

Let `M_remaining = M`. Also maintain a per‑tick `Rejected` set, initially empty.

Define:

```
score(m) = base_priority(m) × priority_scale(m) + age(m) × fairness_scale(m)
```

Computed using **128‑bit intermediate arithmetic**; if the result exceeds `INT64_MAX` it saturates to `INT64_MAX`; if below `INT64_MIN` it saturates to `INT64_MIN`. Overflow never fatal.

Total order:
1. Higher score first.
2. If tie, lexicographically smaller `match_key` (using structured tuple comparison, not JSON).

Select `m* = argmax_{m ∈ M_remaining \ Rejected} score(m)`.

If `M_remaining \ Rejected = ∅`, the tick ends with **no commit** (see Rule 6).

Transition:

```
⟨⟨G, C, M_prev, M⟩, IR⟩ ⇒ ⟨⟨G, C, M_prev, M, m*, Rejected⟩, IR⟩
```

### Rule 3: PLAN (Syntax‑Directed Compilation)

Define `Compile(IR, G, m*)` by structural recursion over the rule’s action block `A`. It produces a **Canonical Action Trace** `α̂` (primitive action sequence) and a **read set** `ℛ`.

The judgment:

```
ℰ ⊢ ⟨A, G⟩ ⇓ ⟨α̂, ℛ⟩
```

where `ℰ` is the environment from `m*` bindings.

**Base case (empty block):**

```
ℰ ⊢ ⟨∅, G⟩ ⇓ ⟨[], ∅⟩
```

**UpdateField:**

```
ℰ ⊢ ⟨e, G⟩ ⇓ ⟨v, ℛ_e⟩   x_id = ℰ(x)   ℰ ⊢ ⟨A_tail, G⟩ ⇓ ⟨α̂_tail, ℛ_tail⟩
────────────────────────────────────────────────────────────────────────────
ℰ ⊢ ⟨UpdateField(x, f, e) · A_tail, G⟩ ⇓ ⟨[UpdateField(x_id, f, v)] · α̂_tail,
                                            ℛ_e ∪ {FieldRead(x_id, f, field_version)} ∪ ℛ_tail⟩
```

**DeleteNode (with implicit edge deletion):**

```
x_id = ℰ(x)
edges = GetIncidentEdgesSorted(x_id, G)   // ORDER_CANONICAL by edge identifier
α̂_edges = [DeleteEdge(e) for e in edges]
ℛ_edges = ⋃_{e∈edges} {AdjacencyRead(x_id, e.type, out, adj_version), EdgeExistence(e, existence_version)}
ℰ ⊢ ⟨A_tail, G⟩ ⇓ ⟨α̂_tail, ℛ_tail⟩
──────────────────────────────────────────────────────────────────────────────
ℰ ⊢ ⟨DeleteNode(x) · A_tail, G⟩ ⇓ ⟨α̂_edges · [DeleteNode(x_id)] · α̂_tail,
                                    ℛ_edges ∪ {NodeExistence(x_id, existence_version)} ∪ ℛ_tail⟩
```

**CreateNode, CreateEdge, EmitEvent** – similar structural rules, each recording appropriate reads and version snapshots. For `EmitEvent`, payload expressions are evaluated to values during PLAN; `α̂` stores the evaluated payload.

**Context‑freeness invariant:** Evaluation depends only on the subterm, the immutable environment `ℰ`, and the fixed graph snapshot `G`.

If compilation encounters a non‑fatal validation error (duplicate field update, missing mandatory field), the candidate `m*` is added to `Rejected` and SELECT is re‑invoked.

Transition:

```
⟨⟨G, C, M_prev, M, m*, Rejected⟩, IR⟩ ⇒ ⟨⟨G, C, M_prev, M, m*, Rejected, α̂, ℛ⟩, IR⟩
```

### Rule 4: COMMIT

**Premises:**

1. **Version validation:** For every read `r ∈ ℛ`:
   - `NodeExistence(id, v)` → node exists and `existence_version[id] == v`.
   - `FieldRead(id, f, v)` → `field_version[id][f] == v`.
   - `ExtentRead(type, v)` → `extent_version[type] == v`.
   - `AdjacencyRead(node, type, dir, v)` → `adjacency_version[node][type][dir] == v`.
   - (Analogous for edge reads.)

2. **Structural validation:**
   - No duplicate `UpdateField` on same `(id, f)`.
   - No duplicate `DeleteEdge` on same edge.
   - All targets exist (or are created earlier in `α̂`).
   - No dangling identifiers after applying `α̂`.
   - All constraints satisfied (re‑evaluated if desired, but version validation suffices; the spec leaves this optional but deterministic).

3. **Counter overflow pre‑check:** For every counter that would be incremented, ensure `post_value ≤ INT64_MAX`. Overflow → fatal.

If any validation fails (non‑fatal) → add `m*` to `Rejected` and go back to SELECT. Fatal errors halt and rollback.

**Application:**

- Apply each step in `α̂` in order to a **copy** `G_temp`.
- Update counters `C → C'` according to the version increment table (see §6). Adjacency increments are deduplicated using the earliest occurrence in `α̂` (scan left‑to‑right, maintain a set of already‑processed `(node, edge)` pairs).
- Emit events in the order they appear in `α̂` (payloads already evaluated, stored in `α̂`).

**Match history update:**

```
M_prev' = { match_key(m) → age(m) | m ∈ M }
```

(All matches from the discovery snapshot, not only the committed one.)

Transition:

```
⟨⟨G, C, M_prev, M, m*, Rejected, α̂, ℛ⟩, IR⟩ → ⟨⟨G', C', M_prev'⟩, IR⟩
```

where `C'.tick_counter = C.tick_counter + 1`.

### Rule 5: NO_MATCH (Empty Match Set)

```
M_remaining \ Rejected = ∅
──────────────────────────────────────────────────────────────
⟨⟨G, C, M_prev, M⟩, IR⟩ → ⟨⟨G, C[tick_counter+1], M_prev'⟩, IR⟩
```

`M_prev'` is implementation‑defined but deterministic: either `M_prev` unchanged or cleared (recommended: keep `M_prev` to preserve ages across idle ticks).

The following table shows counter changes **only when a mutation actually occurs** (No‑Op writes do nothing). These are consequences of the structural compilation semantics.

| Operation              | extent | pred(node) | edge_type | edge_pred | adjacency (source.out, target.in) | existence | field_vers |
|------------------------|--------|------------|-----------|-----------|-----------------------------------|-----------|------------|
| CreateNode             | +1     | +1 (each field in supplied map) | -         | -         | -                                 | set to 1  | set to 1 each |

## 8. Determinism Theorem

**Theorem:** For any configuration `⟨Σ, IR⟩`, there is at most one `⟨Σ', IR⟩` such that `⟨Σ, IR⟩ → ⟨Σ', IR⟩`. Consequently, for a given initial state and IR, all conformant engines produce identical observable behavior.

**Proof sketch:**

- `EvalPatterns` is a total function over `G` and `IR` – ordering fixed by tuple lexicographic order.
- `ComputeAge` is a pure lookup.

- `Compile` is defined by structural induction; each clause yields a unique `(α̂, ℛ)` due to canonical ordering and context‑freeness.
- `COMMIT` validation and application are pure functions, with version snapshots enabling deterministic staleness checks.
- `NO_MATCH` handles empty candidate set deterministically.
- No other transition rules exist.

Thus the transition relation is deterministic.

## 4. Revised SELECT Rule – (§5.3 SELECT)

A per‑tick **rejection set** `R` is introduced.  At the start of a tick
`R = ∅`.  The rule now selects from the *remaining* matches.

```text
SELECT

score(m) = base_priority(m)·priority_scale(m) +

   1. higher score first
   2. tie → lexicographically smaller match_key (see §7)

If M_rem ≠ ∅ then

```

*The rejection set `R` is *mutable* only within the current tick; it is cleared
when the tick ends (after COMMIT or NO_MATCH).  This guarantees termination

## 5. Rejection Handling – (§5.4 REJECT)

When a candidate `m*` fails a non‑fatal validation (stale read, duplicate
update, missing target, etc.) the engine executes the following transition
instead of looping back to SELECT unchanged:

```text
REJECT
──────────────────────────────────────────────────────
⟨⟨G, C, M_prev, M, M_rem, m*⟩, IR⟩
   →  ⟨⟨G, C, M_prev, M, M_rem \ {m*}, R ∪ {m*}⟩, IR⟩
```

After the REJECT step the engine immediately re‑enters SELECT on the
updated `M_rem`.  If `M_rem` becomes empty, the NO_MATCH rule fires.

## 6. Canonical `match_key` – (§7.1 Match‑Key Canonicalisation)

The `match_key` is **not** a JSON string in the runtime engine; it is a
structured tuple that can be compared directly with lexicographic order.
Only when a golden file is produced is the tuple rendered as canonical JSON.

```
match_key = ( rule_id , [ (var_name₁ , element_id₁) ,
                         (var_name₂ , element_id₂) , … ] )
```

*Ordering of the binding list*  
- The list is sorted **by the variable name** (lexicographic, UTF‑8 bytewise).  
- Each `element_id` is the canonical identifier string `type:seq` where `type`
  is NFC‑normalized and `seq` is a decimal integer with no leading zeros.

*Lexicographic comparison*  
`match_key₁ < match_key₂` iff  

1. `rule_id₁` < `rule_id₂` (UTF‑8 bytewise), or  
2. the rule ids are equal and the first differing pair `(var_name, element_id)`
   is smaller under the same bytewise order.

*Golden‑file representation*
