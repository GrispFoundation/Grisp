# Problems in Candidate 6

## 1. Short-Circuit Contradiction

§2.1 says:

> Short-circuit evaluation is required

but also:

> Dependency extraction includes both operands regardless of runtime short-circuit result.

This creates a semantic mismatch.

Example:

```text
true || MissingNode.field
```

Runtime:

```text
MissingNode.field
```

is never evaluated.

Yet dependency extraction claims the read occurs.

This means:

* PLAN may record reads that never happened.
* stale-read validation can reject a rule due to data never actually inspected.

### Fix

Dependency collection must follow evaluation.

Replace:

```text
read set = union of both operands
```

with:

```text
read set = reads performed by actual evaluation path
```

This preserves observational determinism.

---

# 2. Optional Constraint Re-Evaluation

COMMIT says:

> constraints may be re-evaluated if desired

and

> spec leaves this optional

This is fatal for conformance.

Two engines could:

Engine A:

```text
re-evaluates
```

Engine B:

```text
does not
```

and obtain different results.

### Fix

Either:

```text
re-evaluation forbidden
```

or

```text
re-evaluation mandatory
```

Personally:

```text
forbid re-evaluation
```

because version validation already guarantees snapshot consistency.

---

# 3. NO_MATCH Is Underspecified

§5:

```text
M_prev' is implementation-defined
```

Then immediately:

```text
recommended: keep M_prev
```

Implementation-defined behavior breaks determinism.

### Fix

Specify exactly:

```text
M_prev' = M_prev
```

or

```text
M_prev' = {}
```

Do not allow both.

---

# 4. DeleteNode Dependency Gap

DeleteNode records:

```text
AdjacencyRead(...)
EdgeExistence(...)
NodeExistence(...)
```

But does not explicitly record:

```text
extent_version(edge_type)
```

for the incident-edge enumeration.

If an edge is created between discovery and commit, enumeration changes.

You probably intended adjacency versions to cover this, but the proof relies on that fact.

### Fix

State explicitly:

```text
AdjacencyRead fully protects incident-edge enumeration.
```

or add additional reads.

---

# 5. M_prev Can Grow Forever

Current rule:

```text
M_prev' =
{ match_key(m) -> age(m) | m ∈ M }
```

Good.

But when:

```text
NO_MATCH
```

occurs:

```text
M_prev
```

persists forever.

A system that eventually stops matching anything can retain stale history indefinitely.

### Fix

Define pruning.

Example:

```text
Entries absent from DISCOVER for K consecutive ticks
are removed.
```

or

```text
M_prev only contains current discovery matches.
```

---

# 6. Missing Resource Limit Semantics

You define:

```text
RESOURCE_LIMIT_EXCEEDED
```

but never define:

* memory limit
* match limit
* recursion limit
* graph size limit

Therefore engines may halt at different points.

### Fix

Either:

```text
remove RESOURCE_LIMIT_EXCEEDED
```

or

define normative limits.

---

# 7. CreateNode Version Semantics

Table:

```text
CreateNode:
existence = set to 1
```

Problem:

What if IDs are reused?

Then:

```text
existence_version = 1
```

appears again.

A stale read from an earlier incarnation becomes indistinguishable.

### Fix

Require:

```text
identifiers never reused
```

or

```text
existence_version is globally monotonic
```

# 8. Missing Match-Key Stability Rule

Candidate 6 says:

```text
match_key =
(rule_id, sorted_binding_list)
```

but never explicitly states:

```text
let bindings excluded
```

until earlier prose.

A conformant engine could accidentally include them.

### Fix

Add:

```text
match_key depends only on identifier bindings.
```

as a normative SHALL statement.
