# GRISP DETERMINISTIC KERNEL v0.52 (CANDIDATE)

## Closed Deterministic Structural Operational Semantics (DSOS)

---

## 0. CORE PRINCIPLE

### Determinism Axiom

Every observable output of the system is a pure function of:

```
(G₀, IR, ORDER_CANONICAL rules)
```

No hidden state, no implementation-defined behavior, no nondeterministic iteration.

---

## 1. GLOBAL STATE

The system state is:

```
<G, C, M_prev, tick_counter>
```

Where:

* `G` = graph (nodes, edges, fields)
* `C[type]` = per-type sequence counter
* `M_prev` = previous tick match history (with age metadata)
* `tick_counter` = monotonic integer

---

## 2. IDENTIFIERS (CANONICAL IDENTITY MODEL)

### 2.1 Identifier format

```
ID := type_name ":" sequence_number
```

* `sequence_number` is a 64-bit monotonic integer per type.

### 2.2 Initialization rule

For each type `T`:

```
C[T] = max(existing_ids(T)) + 1
or 0 if none exist
```

### 2.3 Allocation rule (COMMIT only)

On `CreateNode(T)` or `CreateEdge(T)`:

1. `seq = C[T]`
2. Assign `ID = T:seq`
3. Increment `C[T] := C[T] + 1`
4. Record `SequenceCounterRead(T, seq)` in read set

---

## 3. ORDER_CANONICAL

A total order over identifiers:

```
A < B if:
  (type_name lexicographically) OR
  (type equal AND numeric seq ascending)
```

Used for ALL iteration, sorting, and serialization.

---

## 4. GRAPH MODEL

### Nodes

```
Node := { id, type, fields }
```

### Edges

```
Edge := { id, type, source, target, fields }
```

Edges DO NOT encode structure in ID.

---

## 5. DISCOVER PHASE (MATCH ENUMERATION)

### 5.1 Traversal order

All enumeration is deterministic:

```
for node in ORDER_CANONICAL(G.nodes):
    for rule in IR.rules in fixed order:
        evaluate patterns using adjacency:
            edges sorted by ORDER_CANONICAL(edge_id)
```

### 5.2 Binding generation

Bindings are produced in fixed order and sorted:

```
sorted_binding_list :=
    sort_by(binding_name lexicographically UTF-8)
    then by ORDER_CANONICAL(binding_value)
```

### 5.3 match_key

```
match_key = (rule_id, sorted_binding_list)
```

---

## 6. PLAN PHASE (SNAPSHOT SEMANTICS)

### 6.1 Snapshot rule

All evaluation occurs on immutable snapshot:

```
G_snap = result of DISCOVER
```

No α̂ action may affect evaluation.

### 6.2 Expression evaluation

* Uses only `G_snap`
* Left-to-right evaluation
* No intermediate visibility of α̂

---

## 7. MATCH SELECTION

### 7.1 Retry rule

```
MAX_RETRIES = max(|M|, 1024)
```

If no valid match after retries → NO_MATCH

---

## 8. NO_MATCH BEHAVIOR

### 8.1 Deterministic rule (MANDATORY)

```
M_prev' = M_prev
tick_counter++
```

### 8.2 Aging model

```
age(m) = tick_counter - last_seen_tick(m)
```

* Updated deterministically each tick
* Optional GC allowed:

```
if age(m) > 2^32 → may remove
```

### 9.1 Constraint validation (MANDATORY)

After applying α̂ to `G_temp`:

```

```

No optional behavior exists.

### 9.2 Counter updates

All updates are applied in α̂ order.

```
C[type]              // sequence counters
```

All other version counters (predicate/field/adjacency/etc.) are REMOVED.

Determinism relies on ORDER_CANONICAL, not version graphs.

* **Deterministic Allocation:** All identities and state changes are explicit, monotonic, and recorded.

## 2.0 Identifier & Schema System

### 2.1 Identity Allocation

Identifiers (IDs) are immutable strings defined as `type_name + ":" + seq`.

* **Counter Initialization:** For every type $T$, the sequence counter $C[T]$ is initialized to $\max(\text{existing\_ids}_T) + 1$. If no instances exist, $C[T] = 0$.


* **Allocation Rule:** During the `COMMIT` phase, `CreateNode` and `CreateEdge` operations read $C[T]$, use the value for the ID, and increment $C[T]$ by 1. The ID must be unique and monotonic per type namespace.


* **Sequence Records:** All ID generations must be recorded in the Action Trace ($\hat{\alpha}$) with a `SequenceCounterRead` and `SequenceCounterWrite` event.



### 2.2 Schema Definitions

* **Validation:** Engines must validate `initial_state` and all mutations against this schema.
* **Hash:** A `type_definitions_hash` (SHA-256 of the canonical JSON) is required to ensure engine-wide schema agreement.


* **Mandatory Fields:** Fields marked as `mandatory: true` must be populated on creation or default-initialization.

## 3.0 Canonical Match Discovery

DISCOVER must enumerate matches using a total, nested iteration order.

### 3.1 Traversal Order

1. **Nodes:** Iterate all nodes $n$ in `ORDER_CANONICAL(node_id)`.


2. **Edges:** For each node, iterate incident edges $e$ in `ORDER_CANONICAL(edge_id)`.


3. **Pattern Order:** Follow the explicit pattern definition order in the IR.



### 3.2 `match_key` Construction

The `match_key` is a hash of `(rule_id, sorted_binding_list)`.

* **Serialization:** `sorted_binding_list` is a list of `(var_name, value)` tuples.


* **Sorting:**
1. Sort by `var_name` (UTF-8 lexicographic).


2. Sort by `value` using `ORDER_CANONICAL` recursively.

## 4.0 Lifecycle & Lifecycle Rules

### 4.1 NO_MATCH Policy

When the match set $M$ is empty or all matches are rejected:

* **M_prev Preservation:** $M\_prev' = M\_prev$. Match ages (last-seen-tick) continue to increment.


* **Garbage Collection:** Entries in $M\_prev$ with `last_seen_tick < current_tick - 1024` are deterministically pruned.


* **Tick Counter:** Always increments.



### 4.2 COMMIT Phase

* **Mandatory Validation:** All constraints defined in $\phi$ MUST be re-evaluated against the post-action snapshot $G_{temp}$.


* **Fatal Errors:** Constraint violation results in a fatal error `CONSTRAINT_VIOLATION` (or triggers a non-fatal rejection depending on the engine's error handling policy; this must be consistent).


* **Retry Limit:** SELECT retries are bounded by $|M|$ (the discovery set size). If all $|M|$ are rejected, the tick terminates as `NO_MATCH`.

### 0. Core Principles (revised)

1. **Single semantic object** — The kernel state is the tuple \(\Sigma = \langle G, C, M_{\text{prev}}, ID\_State \rangle\). No other persistent runtime artifacts are permitted.  
   - **G** — typed property graph (nodes, edges, fields, identifiers).

   - **ID_State** — deterministic per-type sequence counters used for id allocation.

2. **Determinism by construction** — Every choice point is resolved by a total, canonical order or a single mandated policy. No optional branches or implementation-defined alternatives remain.

3. **Snapshot semantics** — DISCOVER produces an immutable snapshot \(G_0\). All expression evaluation and dependency extraction in DISCOVER and PLAN use \(G_0\) only.

4. **Canonical Action Trace (CAT / \(\hat{\alpha}\))** — PLAN produces a canonical, fully-evaluated primitive action sequence with no unresolved references; temporary tokens are resolved deterministically in COMMIT.

5. **Atomic commit** — Validation, application, and counter updates are a single atomic step. COMMIT either succeeds and advances the authoritative state or fails and rolls back to the pre-tick state.

### 1. State Model (normative)

A configuration is:

\[
\Sigma = \langle G, C, M_{\text{prev}}, ID\_State \rangle
\]

**G — Graph model**

- **Nodes**: each node has an **Identifier** of the form `type:seq` (string), a **type_name**, and a map of **fields** (all fields present per schema).
- **Edges**: each edge has an **Identifier** `edge_type:seq`, a **type_name**, a **src** node id, a **tgt** node id, and a map of **fields**.
- **Fields**: typed values (Integer, FixedPoint(scale), Boolean, String, Identifier, List, Map). No implicit nulls; presence is governed by the schema.

**C — Counters**

- **tick_counter**: signed 64-bit integer, starts at 0.
- **Version counters** (canonical set):
  - `element_version[id]` — signed 64-bit integer per node or edge.
  - `type_extent_version[type_name]` — signed 64-bit integer per type.
  - `adjacency_version[node_id][edge_type][dir]` — signed 64-bit integer per endpoint, per edge type, per direction (`in`/`out`).
- Missing counters in initial state are treated as 0.

**ID_State — Identifier allocation**

- For each type `T` (node or edge type), `ID_State[T]` is a signed 64-bit sequence counter.
- Initialization: `ID_State[T] = max_seq_in_initial_state(T) + 1` if any existing elements of type `T` exist; otherwise `0`.
- Allocation rule: final id allocation occurs **only** during COMMIT and follows the deterministic rule in Section 4.2.

**M_prev — Match history**

- `M_prev` maps `match_key` → `last_seen_tick` (signed 64-bit).
- `last_seen_tick` is the tick number when the match was last discovered (DISCOVER) or updated.
- `M_prev` is preserved across idle ticks per the NO_MATCH rule (Section 5.5) and is pruned deterministically (see GC policy).

**Invariants (checked after each successful COMMIT):**

- No dangling edges (source/target exist).
- No dangling identifier references (recursively through lists/maps).
- All declared schema constraints satisfied.
- No cycles in identifier references (detected via deterministic visited-set traversal).

### 2. Canonical IR Syntax (inductive) — updates

The IR remains the canonical JSON format with the same grammar as v0.51, with the following clarifications and additions:

**2.1 Expressions**

- Grammar extended with unary `!e`, indexing `e1[e2]`, list and map literals.
- **Evaluation model**: All expressions are evaluated deterministically left-to-right where applicable; `&&` and `||` short-circuit at runtime, but **dependency extraction** records reads from both operands (conservative). **2.4 Let bindings**

- Let bindings are evaluated during DISCOVER/PLAN against \(G_0\). Any runtime error (division by zero, missing key) during let evaluation is **non-fatal** for DISCOVER (the candidate match is rejected) and recorded as a rejected-match reason.

**2.5 Actions**

- Actions are the same primitives. PLAN must produce a canonical \(\hat{\alpha}\) where all expressions are evaluated to concrete values (no unresolved expressions or temporary ids).

**2.6 Rule Definition**

### 3. Deterministic Ordering (ORDER_CANONICAL) — precise rules

ORDER_CANONICAL is the total order used everywhere. Rules:

1. **Strings**: UTF-8 bytewise lexicographic after NFC normalization (Unicode version specified in Appendix).
2. **Identifiers**: compare `(type_name, sequence_number)` lexicographically: `type_name` by UTF-8 lexicographic, then numeric `sequence_number`.
3. **Lists**: element-wise lexicographic using ORDER_CANONICAL.
4. **Maps**: compare keys in UTF-8 order; compare values by ORDER_CANONICAL.
5. **Numbers**: Integer < FixedPoint; within same kind, numeric comparison.
6. **Booleans**: `false < true`.

ORDER_CANONICAL is total and must be used for:

- Node and edge iteration.
- Binding value comparisons.
- match_key canonicalization.
- Sorting incident edges for DeleteNode expansion.
- Map literal iteration and serialization.

### 4. Identifier allocation and canonical id rules

**4.1 Identifier format**

- Identifiers are strings `type:seq` where `seq` is a decimal representation of a signed 64-bit integer.

**4.2 Allocation algorithm (normative)**

- **When**: final allocation occurs during COMMIT only.
- **How**:
  1. During PLAN, new elements are represented by **temporary tokens**: `(rule_id, match_key, local_name)`. PLAN records `SequenceCounterRead(type, current_value)` in the read trace if it needs to know the next sequence (see action rules).
  2. During COMMIT, when applying \(\hat{\alpha}\) left-to-right, for each `CreateNode(type, ...)` or `CreateEdge(type, ...)` that requires a new id:
     - Read `ID_State[type]` (value `v`), assign `new_seq = v`, set `new_id = type + ":" + new_seq`.
     - Increment `ID_State[type] := v + 1`.
     - Record `SequenceCounterWrite(type, new_seq)` in the commit trace.
- **Determinism**: Because COMMIT applies \(\hat{\alpha}\) left-to-right and ID_State is part of the authoritative state, id allocation is deterministic across conformant engines.

**4.3 Initial state rule**

- On initial load, `ID_State[type] = max(seq of existing elements of type) + 1` or `0` if none.

### 5. Operational Semantics (Small-Step SOS) — revised rules

All transitions are deterministic functions of the current configuration and IR. The extended ephemeral artifacts used during a tick are `M` (discovered matches), `Rejected` (per-tick), selected match `m*`, \(\hat{\alpha}\), and read set `R`. These artifacts are ephemeral and not part of \(\Sigma\) after COMMIT.

#### Rule 1: DISCOVER (deterministic)

**EvalPatterns(G, IR) = M**:

- Build immutable snapshot \(G_0 = G\).
- Enumerate candidate matches using the **Canonical Nested Iteration Model**:
  1. Iterate nodes in ORDER_CANONICAL(node_id).
  2. For each rule in ORDER_CANONICAL(rule_id).
  3. For each pattern component in rule pattern order, perform nested iteration; for `MatchEdge` use adjacency lists sorted by ORDER_CANONICAL(edge_id).
- Evaluate constraints and let bindings left-to-right; short-circuit for `&&`/`||` at runtime, but record dependency reads for both operands.
- For each match `m` produce:
  - `match_key = (rule_id, CanonicalSerialize(sorted_binding_list))` (Section 6).
  - `bindings`, `let_values` (diagnostic), and read trace `R_m` (all graph elements accessed with version snapshots).
- **Age assignment**:
  - If `match_key` in `M_prev`, `age(m) = current_tick - M_prev[match_key]`.
  - Else `age(m) = 0`.
- **Transition (ephemeral)**:
  \[
  \langle\langle G, C, M_{\text{prev}}, ID\_State\rangle, IR\rangle \Rightarrow \langle\langle G, C, M_{\text{prev}}, ID\_State, M\rangle, IR\rangle
  \]

#### Rule 2: SELECT (with bounded retry)

- Initialize `Rejected := ∅`. Let `M_remaining := M`.
- Define `score(m) = base_priority(m) * priority_scale(m) + age(m) * fairness_scale(m)` computed in 128-bit intermediate and saturated to INT64 bounds. If saturation occurs, the saturated value is used deterministically.
- Total order for selection:
  1. Higher `score` first.
  2. If tie, lexicographically smaller `match_key` (ORDER_CANONICAL).
- Select `m* = argmax_{m ∈ M_remaining \ Rejected} score(m)`.
- If `M_remaining \ Rejected = ∅` → go to NO_MATCH (Rule 5).
- **Retry bound**: SELECT may reject at most `|M|` distinct matches per tick. If `Rejected.size() == |M|`, transition to NO_MATCH.
- **Transition**:
  \[
  \langle\langle G, C, M_{\text{prev}}, ID\_State, M\rangle, IR\rangle \Rightarrow \langle\langle G, C, M_{\text{prev}}, ID\_State, M, m^*, Rejected\rangle, IR\rangle
  \]

#### Rule 3: PLAN (syntax-directed compilation to \(\hat{\alpha}\))

- **Snapshot**: PLAN evaluates expressions and builds \(\hat{\alpha}\) using the immutable snapshot \(G_0\).
- **Judgment**: \(E \vdash \langle A, G_0 \rangle \Downarrow \langle \hat{\alpha}, R \rangle\).
- **Action rules** (examples; exhaustive list in Appendix):
  - `UpdateField(x,f,e)`: evaluate `e` on \(G_0\) → value `v`; record `FieldRead(x_id,f,field_version_snapshot)` in `R`; append `UpdateField(x_id,f,v)` to \(\hat{\alpha}\).
  - `DeleteNode(x)`: expand to `DeleteEdge(e)` for incident edges sorted by ORDER_CANONICAL(edge_id) using `GetIncidentEdgesSorted(x_id, G_0)`; record adjacency and edge existence reads for each edge in `R`; append expanded actions then `DeleteNode(x_id)`.
  - `CreateNode(x,type,fields)`: evaluate field expressions on \(G_0\); record `TypeExtentRead(type, extent_version_snapshot)` and `SequenceCounterRead(type, ID_State[type])` in `R`; append `CreateNode(temp_token, type, evaluated_fields)` to \(\hat{\alpha}\).
  - `CreateEdge` similar, recording node existence and adjacency reads for both endpoints.
  - `EmitEvent` payloads are evaluated on \(G_0\) and stored as concrete values in \(\hat{\alpha}\).
- **Compilation errors**:
  - Non-fatal validation errors (duplicate field update, missing mandatory field) cause the candidate `m*` to be added to `Rejected` and SELECT is retried.
  - Fatal errors (division by zero in a let that is not recoverable, fixed-point overflow) abort the tick with an error snapshot.
- **Transition**:
  \[
  \langle\langle G, C, M_{\text{prev}}, ID\_State, M, m^*, Rejected\rangle, IR\rangle \Rightarrow \langle\langle G, C, M_{\text{prev}}, ID\_State, M, m^*, Rejected, \hat{\alpha}, R\rangle, IR\rangle
  \]

#### Rule 4: COMMIT (atomic validation and application)

**Premises (all mandatory):**

1. **Version validation**: For every read `r ∈ R`:
   - `NodeExistence(id, v)` → node exists in `G` and `element_version[id] == v`.
   - `FieldRead(id,f,v)` → `element_version[id] == v` and field presence matches schema.
   - `TypeExtentRead(type, v)` → `type_extent_version[type] == v`.
   - `AdjacencyRead(node,type,dir,v)` → `adjacency_version[node][type][dir] == v`.
   - `SequenceCounterRead(type, v)` → `ID_State[type] == v` (pre-commit snapshot).
   - `EdgeExistence(edge_id, v)` → `element_version[edge_id] == v`.
   - All checks are **mandatory**; any mismatch is **non-fatal** for this candidate (add `m*` to `Rejected` and retry SELECT) unless the mismatch indicates a fatal condition (counter overflow, invariant violation).

2. **Structural validation**:
   - No duplicate `UpdateField` on same `(id,f)` in \(\hat{\alpha}\).
   - No duplicate `DeleteEdge` on same `edge_id`.
   - All targets referenced by actions either exist in `G` or are created earlier in \(\hat{\alpha}\) (temporary tokens resolved deterministically).
   - No dangling identifiers after applying \(\hat{\alpha}\) to `G_temp`.
   - **Constraint re-evaluation**: All rule constraints φ are **re-evaluated** against `G_temp` after applying \(\hat{\alpha}\). If any constraint fails, treat as non-fatal rejection (add `m*` to `Rejected`).

3. **Counter overflow pre-check**:
   - For every counter that would be incremented, ensure post_value ≤ INT64_MAX. If overflow would occur, this is **fatal** (`COUNTER_OVERFLOW`) and the tick aborts with rollback.

**Application (atomic):**

- Apply each step in \(\hat{\alpha}\) left-to-right to a copy `G_temp`, resolving temporary tokens to final ids using the deterministic allocation algorithm (Section 4.2). While applying, record the set of counter increments in left-to-right order.
- After successful application to `G_temp` and passing structural validation, update authoritative `G := G_temp`.
- Update counters `C` and `ID_State` according to the recorded increments in the same left-to-right order. Adjacency increments are deduplicated by canonical key `(node_id, edge_id, direction)` using earliest occurrence in \(\hat{\alpha}\).
- Emit events in the order they appear in \(\hat{\alpha}\).
- **Match history update**:
  - For every `m ∈ M` discovered in DISCOVER, set `M_prev[match_key(m)] := C.tick_counter` (the tick number being committed).
  - For matches not present in the new `G` (post-commit), remove their entries deterministically (see GC policy).
- **Advance tick counter**: `C.tick_counter := C.tick_counter + 1`.
- **Transition**:
  \[
  \langle\langle G, C, M_{\text{prev}}, ID\_State, M, m^*, Rejected, \hat{\alpha}, R\rangle, IR\rangle \rightarrow \langle\langle G', C', M_{\text{prev}}', ID\_State'\rangle, IR\rangle
  \]

**Failure modes**:

- **Non-fatal**: stale read, duplicate field update, missing target → add `m*` to `Rejected`, retry SELECT (bounded).
- **Fatal**: counter overflow, division-by-zero in a committed expression, invariant violation that cannot be resolved → abort tick, rollback to pre-tick state, produce error object in golden file.

#### Rule 5: NO_MATCH (Empty Match Set) — canonical policy

- If `M_remaining \ Rejected = ∅`:
  - **Deterministic action**:
    - Preserve `M_prev` unchanged except for deterministic pruning (GC).
    - Advance `C.tick_counter := C.tick_counter + 1`.
  - **GC policy**: deterministically remove `match_key` entries with `last_seen_tick < C.tick_counter - GC_WINDOW`. `GC_WINDOW` is a normative constant (default 1024) for conformance tests; engines may expose a configuration but conformance uses the canonical default.
  - **Transition**:
    \[
    \langle\langle G, C, M_{\text{prev}}, ID\_State, M\rangle, IR\rangle \rightarrow \langle\langle G, C[tick+1], M_{\text{prev}}'\rangle, IR\rangle
    \]

### 6. Version Increment Rules (complete canonical table)

All increments are applied only when the corresponding mutation actually occurs. The canonical counters are `element_version`, `type_extent_version`, and `adjacency_version`. The following table is normative (rows show action → counters changed):

| Operation | element_version | type_extent_version | adjacency_version |
|---|---:|---:|---:|
| CreateNode(type, fields) | `element_version[new_node] := 1` | `type_extent_version[type] += 1` | none |
| DeleteNode(node) | remove `element_version[node]` (or set to 0) | `type_extent_version[type(node)] += 1` | increments for each incident `(node, edge_id, dir)` handled by expanded DeleteEdge; deduplicated |
| CreateEdge(type, src, tgt, fields) | `element_version[new_edge] := 1` | `type_extent_version[type] += 1` | `adjacency_version[src][type][out] += 1`; `adjacency_version[tgt][type][in] += 1` |
| DeleteEdge(edge) | remove `element_version[edge]` | `type_extent_version[type(edge)] += 1` | `adjacency_version[src][type][out] += 1`; `adjacency_version[tgt][type][in] += 1` |
| UpdateField(element, field, v) | `element_version[element] += 1` | none | none |

- **Deduplication**: adjacency increments are deduplicated by `(node_id, edge_id, direction)` using earliest occurrence in \(\hat{\alpha}\).
- **SequenceCounter writes**: `ID_State[type]` increments are recorded as `SequenceCounterWrite(type, new_seq)` and applied in COMMIT.

### 7. Numeric Model (complete)

- **Integers**: signed 64-bit.
- **Fixed-point**: scaled integers with scale ∈ \([0,18]\).
  - **Serialization**: scale 0 → JSON number without decimal (e.g., `42`); scale > 0 → JSON string with decimal point and exactly `scale` fractional digits (e.g., `"12.5000"` for scale 4).
  - **Promotion**: Integer promoted to FixedPoint(0) when combined with FixedPoint.
  - **Scale propagation**:
    - `+`, `-`: result_scale = max(scale_left, scale_right).
    - `*`: result_scale = scale_left + scale_right. If result_scale > 18 → **fatal** `FIXED_POINT_SCALE_OVERFLOW`.
    - `/`: result_scale = scale_left. Division uses big-integer intermediates; if intermediate bit-length > 4096 → `RESOURCE_LIMIT_EXCEEDED`.
  - **Rounding**: truncation toward zero for division and `to_integer`.
  - **Overflow**: any arithmetic overflow beyond representable range → fatal `INTEGER_OVERFLOW` or `FIXED_POINT_SCALE_OVERFLOW` as appropriate.

### 8. Canonical Serialization (Golden File) — strict schema

Golden file is UTF-8 JSON with lexicographically sorted keys and canonical ordering:

Top-level structure:

```json
{
  "ir_schema_version": "1.0",
  "type_definitions_hash": "<sha256-hex>",
  "initial_state": { "graph": { "nodes": [...], "edges": [...] }, "versions": {...} },
  "ticks": [ ... ],
  "final_state": { ... }
}
```

- **Nodes**: array sorted by ORDER_CANONICAL(node_id). Each node object: `{"id":"type:seq","type":"type","fields":{...},"v":element_version}` with fields map keys sorted.
- **Edges**: array sorted by ORDER_CANONICAL(edge_id). Each edge object: `{"id":"type:seq","type":"type","src":"...","tgt":"...","fields":{...},"v":element_version}`.
- **Ticks**: each tick record:
  ```json
  {
    "tick_number": 0,
    "selected_match_key": { "rule_id": "...", "bindings": {...} } | null,
    "committed_changes": [ { "op":"CreateNode", "id":"Person:5", ... }, ... ],
    "events": [ { "rule_id":"...", "payload": ... } ]
  }
  ```
- **Error object**: if a fatal error occurs, `ticks` is replaced by `"error": { "code": "...", "context": {...}, "state": {...}, "tick": 0 }`.

**type_definitions_hash**: SHA-256 of canonical JSON serialization of the schema (keys sorted by ORDER_CANONICAL).

### 10. Determinism Theorem (revised sketch)

For any configuration \(\langle \Sigma, IR \rangle\), there is at most one successor \(\langle \Sigma', IR \rangle\) under the transition relation defined by Rules 1–5 because:

- DISCOVER is a total function: enumeration order and binding sorting are canonical.

- All previously optional behaviors are now fixed; resource limits and GC are canonical defaults for conformance.

Thus, for identical IR and identical initial \(\Sigma\), all conformant engines produce identical committed transitions, emitted events, and golden files.

## Preamble

This specification defines the GRISP Deterministic Kernel as a closed, formally deterministic graph‑rewrite calculus. It supersedes all previous versions (v0.49, v0.50, v0.51) and resolves their architectural inconsistencies by unifying pattern matching, dependency tracking, action compilation, and commit into a single structural operational semantics with trace projection.

For identical **Canonical IR** and identical **initial state**, all conformant engines **MUST** produce identical observable behaviour:

- Committed state transitions  
- Emitted events  
- Golden file output (byte‑for‑byte identical JSON)

All normative rules are mandatory. No hidden nondeterminism, runtime inference, or dual semantic models are permitted.

## 0. Core Principles

1. **Single semantic object** – State is a tuple `<G, C, M_prev>` with no hidden runtime artifacts.  
2. **Determinism by construction** – All choice points eliminated via total orders and structural recursion.  
3. **Read effects as derivation** – Dependencies are induced by syntax‑directed translation, with version snapshots recorded at read time.  
4. **Canonical Action Trace (CAT)** – The execution trace is a projection of the compilation derivation.  
5. **Atomic commit** – Validation, application, and counter update form a single, rollback‑able step.

## 1. State Model

A configuration is:

```
Σ = <G, C, M_prev>
```

- **G** – Typed property graph (nodes, edges, fields, identifiers). No nulls; all fields defined per type schema.  
- **C** – Counters (signed 64‑bit integers):  
  - `tick_counter` (starts at 0) – authoritative tick number.  
  - **Sequence counters** per node/edge type – start at `max(initial_seq_of_type) + 1` (or 0 if no initial instances).  
  - **Version counters** (simplified, see §6):  
    - `element_version[id]` – increments on any mutation of that element.  
    - `type_extent_version[type]` – increments on creation or deletion of an element of that type.  
    - `adjacency_version[node][type][dir]` – increments when an edge of given type and direction is added/removed.  
- **M_prev** – Previous match state: a map from `match_key` to **last_tick_seen** (integer). Initialised empty.

**Invariants** (checked after each commit):

- No dangling edges (source/target exist).  
- No dangling identifier references (recursively through lists/maps).  
- All declared constraints satisfied.  
- No cycles in identifier references (detected via visited set).

## 2. Canonical IR Syntax (Inductive)

The IR is a deterministic, canonical JSON format.

### 2.1 Expressions

```
e ::= k                           // literal (Integer, FixedPoint(s), Boolean, String, Identifier)
    | x                           // variable (pattern binding or let)
    | x.f                         // field access
    | e1 ⊕ e2                     // binary operator
    | len(e)                      // list length
    | to_fixed(e, scale)          // conversion to FixedPoint
    | to_integer(e)               // truncation to Integer
    | [e1, e2, ...]               // list literal
    | { "k1": e1, "k2": e2, ... } // map literal (keys sorted)
    | e1[e2]                      // list index or map key lookup
    | !e                          // logical NOT (boolean)

⊕ ::= + | - | * | / | // | % | < | <= | > | >= | == | != | && | ||
```

All operations have **checked semantics** (overflow → fatal).  
Short‑circuit evaluation required left‑to‑right for `&&` and `||`.  
Dependency extraction records **only the reads that are actually evaluated** (i.e., the short‑circuited branch is **not** added to the read set). This matches runtime behaviour and avoids spurious rejections.

### 2.2 Patterns

```
P ::= ∅
    | MatchNode(x, type_name) · P
    | MatchEdge(x, type_name, src, tgt) · P
```

Patterns are enumerated in **lexicographic order of the tuple of bound identifiers** (in pattern order), using `ORDER_CANONICAL` for each component. The actual graph traversal order is fixed in §5 (Rule 1 – DISCOVER).

### 2.3 Constraints (where clause)

```
φ ::= True
    | e1 == e2
    | e1 != e2
    | e1 < e2
    | e1 <= e2
    | e1 > e2
    | e1 >= e2
    | φ1 && φ2
    | φ1 || φ2
    | (φ)
```

`&&` and `||` follow the same short‑circuit and dependency rules as §2.1.

### 2.4 Let Bindings

```
B ::= ∅
    | Let(x, e) · B
```

Evaluated during discovery; do not affect `match_key`. Reads induced by `e` are recorded in the read trace.

### 2.5 Actions

```
a ::= CreateNode(x, type_name, {f1: e1, ...})
    | CreateEdge(x, type_name, src, tgt, {f1: e1, ...})
    | UpdateField(target, field, e)
    | DeleteEdge(e)
    | DeleteNode(x)
    | EmitEvent(event_type, [e1, ...])
```

### 2.6 Rule Definition

```
Rule ::= Rule(rule_id, base_priority, priority_scale, fairness_scale, P, φ, B, A)
```

- `rule_id` – string matching `[A-Za-z_][A-Za-z0-9_-]*`  
- Priorities: non‑negative integers  
- `A` – action block (sequence of actions)

### 2.7 Type Definitions (Schema)

Every conformant engine MUST accept a **type definitions** object as part of the initial state. The format is:

```json
{
  "node_types": {
    "Person": {
      "fields": {
        "name": { "type": "string", "mandatory": true },
        "age":  { "type": "integer", "mandatory": false, "default": 0 }
      }
    }
  },
  "edge_types": {
    "Knows": {
      "fields": {
        "since": { "type": "fixedpoint(0)", "mandatory": true }
      }
    }
  }
}
```

- Allowed field types: `"integer"`, `"fixedpoint(N)"` (N = 0‑18), `"boolean"`, `"string"`, `"identifier"`, `"list"`, `"map"`.  
- `mandatory`: if `true`, the field must be supplied in `CreateNode`/`CreateEdge`. If `false` and missing, the `default` value is used.  
- `type_definitions_hash` is the SHA‑256 of the canonical JSON representation (keys sorted, no whitespace).

The kernel **rejects** any IR that references an undefined type or violates mandatory field rules.

## 3. Deterministic Ordering (`ORDER_CANONICAL`)

For any two values `x` and `y`:

- **Strings**: UTF‑8 bytewise lexicographic, after NFC normalisation.  
- **Identifiers**: compare `(type_name, sequence_number)` lexicographically (type_name UTF‑8, then numeric).  
- **Lists**: element‑wise lexicographic.  
- **Maps**: compare keys in UTF‑8 order, then values.  
- **Booleans**: `false` < `true`.  
- **Integers and FixedPoint**: numeric order (after aligning scales for FixedPoint).  
- **Mixed types**: order by type tag (Integer < FixedPoint < Boolean < String < Identifier < List < Map).

Used for: pattern enumeration, sorting incident edges, `match_key` ordering, map literal iteration, tie‑breaking for min/max/sort.

---

## 4. Numeric Model

- **Integers**: signed 64‑bit. Overflow → fatal `INTEGER_OVERFLOW`.  
- **FixedPoint**: scaled integers, scale 0‑18 inclusive.  
  - Serialisation: scale 0 → JSON number (e.g., `42`). Scale >0 → JSON string with exactly `scale` digits after decimal (e.g., `"12.5000"` for scale 4).  
- **Arithmetic**:
  - Promotion: Integer → FixedPoint(0) when combined with FixedPoint.  
  - Scale propagation:  
    - `+`, `-`: `result_scale = max(scale_left, scale_right)`  
    - `*`: `result_scale = scale_left + scale_right` (if >18 → fatal `FIXED_POINT_SCALE_OVERFLOW`)  
    - `/`: `result_scale = scale_left` (truncation toward zero)  
  - Rounding: truncation toward zero.  
  - Division by zero → fatal.  
- `//` (integer division) on Integers yields Integer, truncated toward zero.  
- `%` (remainder) on Integers: sign follows dividend.  
- Comparisons: align scales to max of the two, then compare numeric values.  
- `to_fixed(e, scale)`: convert to rational (numerator/10^old_scale), truncate toward zero to new scale, represent with given scale.  
- `to_integer(e)`: truncate toward zero.

## 5. Operational Semantics (Small‑Step SOS)

The kernel executes via deterministic transitions over extended configurations that include ephemeral derivation artifacts. The **official** configuration is `<G, C, M_prev>`. The following rules describe the derivation steps; the overall transition `<G, C, M_prev> -> <G', C', M_prev'>` is deterministic.

### Rule 1: DISCOVER (Match Generation)

Define `EvalPatterns(G, IR) = M` as the total set of matches obtained by:

1. **Traversal order** (fixed and total):  
   - Iterate over **node types** in lexicographic order.  
   - For each node type, iterate over nodes of that type sorted by identifier (`ORDER_CANONICAL`).  
   - For each node, iterate over pattern elements in order.  
   - For a `MatchNode`, bind the node.  
   - For a `MatchEdge`, iterate over incident edges of the required type and direction, sorted by **edge identifier**. Bind source/target accordingly.  
   - If multiple `MatchNode` with no connecting edge, take the Cartesian product over nodes (sorted by identifier).  

2. Evaluate constraints and let bindings left‑to‑right with required short‑circuit for `&&`/`||`.  

3. Each match `m` contains:  
   - `match_key = (rule_id, sorted_binding_list)`.  
     - `sorted_binding_list` = list of `(identifier_name, value)` pairs sorted by `identifier_name` (UTF‑8), then by value using `ORDER_CANONICAL`.  
   - `bindings` (identifier → value).  
   - `let_values` (diagnostic).  
   - `read_trace R_m`: all graph elements accessed **at evaluation time** (short‑circuit respected), with version snapshots:  
     - `NodeExistence(id, element_version)`  
     - `FieldRead(id, f, element_version)`  
     - `TypeExtentRead(type, type_extent_version)`  
     - `AdjacencyRead(node, edge_type, dir, adjacency_version)`  
     - `EdgeExistence(edge_id, element_version)`  
     - `SequenceCounterRead(type, value)`

**Age assignment:**  
`age(m) = if match_key in M_prev then current_tick - M_prev[match_key] else 0`  
(Age saturates at `INT64_MAX`.)

Transition (ephemeral):  
`<<G, C, M_prev>, IR> => <<G, C, M_prev, M>, IR>`

### Rule 2: SELECT (with retry semantics)

Let `M_remaining = M`. Maintain a per‑tick `Rejected` set, initially empty.  
Retry limit: `MAX_RETRIES = |M|`. After `MAX_RETRIES` attempts with no commit, the tick ends with NO_MATCH.

Define:  
`score(m) = base_priority(m) * priority_scale(m) + age(m) * fairness_scale(m)`  
(128‑bit intermediate; if result exceeds `INT64_MAX` saturate to `INT64_MAX`; if below `INT64_MIN` saturate to `INT64_MIN`. Overflow never fatal.)

Total order:  
1. Higher `score` first.  
2. If tie, lexicographically smaller `match_key` (using `ORDER_CANONICAL` on tuple).

Select `m* = argmax_{m in M_remaining \ Rejected} score(m)`.  

If `M_remaining \ Rejected = ∅`, go to Rule 5 (NO_MATCH).  

Transition:  
`<<G, C, M_prev, M>, IR> => <<G, C, M_prev, M, m*, Rejected>, IR>`

### Rule 3: PLAN (Syntax‑Directed Compilation)

`Compile(IR, G, m*)` produces a **Canonical Action Trace** `α̂` (primitive action sequence) and a read set `R`.  
All expressions evaluate against the **immutable snapshot `G` from DISCOVER**. No intermediate effects are visible.

**Read set rules (complete):**

| Action | Read set additions |
|--------|--------------------|
| `CreateNode(type, fields)` | `TypeExtentRead(type)`, `SequenceCounterRead(type)`; for each field: `FieldRead` on the new node? (none, since node doesn't exist yet) – but predicate versions are not needed because the node is new. |
| `CreateEdge(type, src, tgt, fields)` | `TypeExtentRead(type)`, `SequenceCounterRead(type)`, `NodeExistence(src)`, `NodeExistence(tgt)`, `AdjacencyRead(src, type, out)`, `AdjacencyRead(tgt, type, in)`, and for each field: `FieldRead` on the new edge (none). |
| `DeleteNode(x)` | `NodeExistence(x)`, `TypeExtentRead(type_of_x)`, for each incident edge (sorted by edge identifier): `EdgeExistence(e)`, `AdjacencyRead(src, e.type, out)`, `AdjacencyRead(tgt, e.type, in)`. |
| `DeleteEdge(e)` | `EdgeExistence(e)`, `AdjacencyRead(src, e.type, out)`, `AdjacencyRead(tgt, e.type, in)`. |
| `UpdateField(target, f, e)` | If target is node: `NodeExistence(target)`, `FieldRead(target, f)`. If edge: `EdgeExistence(target)`, `FieldRead(target, f)`. |
| `EmitEvent(event_type, args)` | Reads from each `e` in args (union). |

**Compilation rules (structural recursion):**  

- Empty block: `∅ → <[], ∅>`  
- `UpdateField(x, f, e) · A_tail`: evaluate `e` to value `v` (using `G`), record `FieldRead(x_id, f, element_version)`. Produce `[UpdateField(x_id, f, v)] · α̂_tail`, union of read sets.  
- `DeleteNode(x)`: expand to `[DeleteEdge(e1), ..., DeleteEdge(en), DeleteNode(x_id)]` where edges are sorted by identifier (`ORDER_CANONICAL`). Read set as above.  
- `CreateNode(x, t, fields)`: evaluate each field expression to value, read `TypeExtentRead(t)`, `SequenceCounterRead(t)`. New identifier is assigned during COMMIT.  
- `CreateEdge(x, t, src, tgt, fields)`: similar, with adjacency reads.  
- `EmitEvent(event, args)`: evaluate each arg to value, store in `α̂`.

If compilation encounters a non‑fatal validation error (duplicate field update, missing mandatory field), the candidate `m*` is added to `Rejected` and SELECT is re‑invoked.

Transition:  
`<<G, C, M_prev, M, m*, Rejected>, IR> => <<G, C, M_prev, M, m*, Rejected, α̂, R>, IR>`

### Rule 4: COMMIT

Premises:

1. **Version validation**: For every read `r` in `R`:  
   - `NodeExistence(id, v)` → node exists and `element_version[id] == v`.  
   - `FieldRead(id, f, v)` → element exists and `field_version` (same as `element_version` for that element) matches.  
   - `TypeExtentRead(type, v)` → `type_extent_version[type] == v`.  
   - `AdjacencyRead(node, type, dir, v)` → `adjacency_version[node][type][dir] == v`.  
   - `EdgeExistence(e, v)` → edge exists and `element_version[e] == v`.  
   - `SequenceCounterRead(type, v)` → current sequence counter for that type equals `v`.  

2. **Structural validation** (simulate `α̂` on a copy `G_temp`):  
   - No duplicate `UpdateField` on same `(id, f)`.  
   - No duplicate `DeleteEdge` on same edge.  
   - No duplicate `DeleteNode` on same node.  
   - All targets exist (or are created earlier in `α̂`).  
   - No dangling identifiers after applying `α̂`.  
   - **All constraints `φ` from the rule must be re‑evaluated** on `G_temp` (mandatory). If any constraint fails, the match is rejected (non‑fatal → add to `Rejected` and retry SELECT).  

3. **Counter overflow pre‑check**: Ensure post‑values ≤ `INT64_MAX`. Overflow → fatal.

If any validation fails (non‑fatal) → add `m*` to `Rejected` and go back to SELECT (up to `MAX_RETRIES`). Fatal errors halt and rollback.

**Application (atomic):**  
- Apply each step in `α̂` in order to `G_temp`.  
- Update counters `C -> C'` according to the **deterministic increment table** (§6).  
- Emit events in the order they appear in `α̂` (payloads already evaluated).  
- **Identifier allocation**: For each `CreateNode`/`CreateEdge`, assign the new identifier using the current sequence counter (pre‑increment value), then increment the sequence counter by 1. Record the assignment.

**Match history update:**  
`M_prev' = { match_key(m) -> current_tick | m in M }`  
(All matches from the discovery snapshot, with `last_tick_seen` set to the current tick number.)  
Entries that have not appeared for `2^32` ticks may be garbage‑collected deterministically (implementation‑defined constant, but must be documented and identical across engines for conformance).

Transition:  
`<<G, C, M_prev, M, m*, Rejected, α̂, R>, IR> -> <<G', C', M_prev'>, IR>`  
where `C'.tick_counter = C.tick_counter + 1`.

### Rule 5: NO_MATCH (Empty Match Set)

`M_remaining \ Rejected = empty`  

```
<<G, C, M_prev, M>, IR> -> <<G, C[tick_counter+1], M_prev'>, IR>
```

where `M_prev' = M_prev` (preserved unchanged).  
The `Rejected` set is discarded; `M_prev` ages are **not** incremented for idle ticks (only the tick counter advances).

## 6. Version Increment Rules (Deterministic Table)

| Operation                     | `type_extent_version[type]` | `element_version[id]` | `adjacency_version[node][type][dir]` | Sequence Counter |
|-------------------------------|-----------------------------|-----------------------|--------------------------------------|------------------|
| `CreateNode(type, fields)`    | +1                          | set to 1 (new node)   | –                                    | +1 (node type)   |
| `DeleteNode(x)`               | +1 (type of x)              | removed               | +1 for each incident edge (both dirs, per edge type) | – |
| `CreateEdge(type, src, tgt, fields)` | +1 (edge type)          | set to 1 (new edge)   | +1 for `(src, type, out)` and `(tgt, type, in)` | +1 (edge type) |
| `DeleteEdge(e)`               | +1 (edge type of e)         | removed               | +1 for `(src, e.type, out)` and `(tgt, e.type, in)` | – |
| `UpdateField(target, f, e)`   | –                           | +1 (target element)   | –                                    | – |

- **Deduplication**: For adjacency increments, use key `(node, edge_type, direction)`. Scan `α̂` left‑to‑right, increment once per unique key.  
- All counters are 64‑bit signed; overflow is fatal (`COUNTER_OVERFLOW`).  
- Initial values: `type_extent_version[type] = 0`, `adjacency_version` all zero, sequence counters as per §1.

## 7. Canonical Serialisation (Golden File)

Output is UTF‑8 JSON with **lexicographically sorted keys**, no extra whitespace.

- **Integer**: JSON number, no leading zeros.  
- **FixedPoint**: scale 0 → number (e.g., `42`); scale >0 → string with decimal point and exactly `scale` digits (e.g., `"12.5000"`).  
- **Boolean**: `true`/`false`.  
- **String**: double‑quoted, escaping `\`, `"`, `\n`, `\r`, `\t`, other controls as `\uXXXX`.  
- **Identifier**: string containing `"type:seq"` (e.g., `"Person:5"`).  
- **List**: `[e1, e2, ...]`.  
- **Map**: `{"k1": v1, "k2": v2, ...}` with keys sorted by `ORDER_CANONICAL`.

**Top‑level golden file structure**:

```json
{
  "ir_schema_version": "1.0",
  "type_definitions_hash": "<hex>",
  "initial_state": { "nodes": [...], "edges": [...] },
  "ticks": [ ... ],
  "final_state": { "nodes": [...], "edges": [...] }
}
```

If a fatal error occurs, the `"ticks"` array is replaced by an `"error"` object.

**Graph state serialisation** (nodes and edges arrays):

- Nodes sorted by identifier (`ORDER_CANONICAL`).  
- Edges sorted by identifier.  
- Each node: `{"id": "...", "type": "...", "fields": {...}}` (fields keys sorted).  
- Each edge: `{"id": "...", "type": "...", "source": "...", "target": "...", "fields": {...}}`.  

**Tick record**:

```json
{
  "tick_number": 0,
  "selected_match_key": { "rule_id": "...", "bindings": {...} } | null,
  "committed_changes": [ ... ],   // α̂ in JSON form
  "events": [ { "rule_id": "...", "payload": ... } ]
}
```

**Error object**:

```json
{
  "code": "COUNTER_OVERFLOW",
  "context": { "location": 0, "snapshot": [...] },
  "state": { ... },
  "tick": 0
}
```

Allowed error codes:  
`INTEGER_OVERFLOW`, `DIVISION_BY_ZERO`, `COUNTER_OVERFLOW`, `FIXED_POINT_SCALE_OVERFLOW`, `INDEX_OUT_OF_BOUNDS`, `MISSING_MAP_KEY`, `INVALID_IR`, `INVARIANT_VIOLATION`, `RESOURCE_LIMIT_EXCEEDED`, `CONSTRAINT_VIOLATION`.

**Resource limits** (minimum every engine must support):  
- `MAX_NODES = 2^31 - 1`  
- `MAX_EDGES = 2^31 - 1`  
- `MAX_MATCHES_PER_TICK = 2^64 - 1` (unlimited in practice)  
- `MAX_RETRIES = |M|` (as per Rule 2)  

If a limit is exceeded, raise `RESOURCE_LIMIT_EXCEEDED` (fatal).

## 8. Determinism Theorem

**Theorem**: For any configuration `<Σ, IR>`, there is at most one `<Σ', IR>` such that `<Σ, IR> -> <Σ', IR>`. Consequently, for a given initial state and IR, all conformant engines produce identical observable behaviour.

**Proof sketch** (fully constructive):

- `EvalPatterns` is a total function: graph traversal order is fixed (node identifier order, edge identifier order, adjacency iteration order).  
- `match_key` construction is deterministic (sorted binding list by name then value).  
- Age computation is a pure lookup from `M_prev`.  
- SELECT uses a total order (score descending, then `match_key` ascending); `Rejected` set grows monotonically per tick, and `MAX_RETRIES` guarantees termination.  
- Compile is defined by structural induction; each clause yields a unique `(α̂, R)` because expressions are evaluated against the immutable snapshot `G`.  
- COMMIT validation and application are pure functions; all optionality removed.  
- NO_MATCH has a single behaviour (`M_prev' = M_prev`).  

Thus the transition relation is deterministic.

### 2.1 Identifier Model (new)

*Identifiers* are strings of the form  

```
type_name : sequence_number
```

where `sequence_number` is a non‑negative 64‑bit integer taken from the **type‑local sequence counter** `C.sequence_counter[type]`.  

- **Node identifiers**: `type_name:seq`.  
- **Edge identifiers**: `edge_type:seq`.  

**Allocation rule (deterministic):**  

During **COMMIT**, when a `CreateNode` or `CreateEdge` action is applied:

1. Read the current counter `c = C.sequence_counter[type]`. Record `SequenceCounterRead(type, c)` in the read‑trace.  
2. Allocate identifier `id = type_name:c`.  
3. Increment the counter: `C.sequence_counter[type] := c + 1`. Record `SequenceCounterWrite(type, c+1)` in the write‑trace.  

The identifier is immutable after creation.  

---

### 2.2 Schema Language (new)

A **type definition** is a JSON object stored in the initial state under the key `"type_definitions"`. The canonical JSON schema is:

```json
{
  "node_types": {
    "Person": {
      "fields": {
        "name": { "type": "string", "mandatory": true },
        "age":  { "type": "integer", "mandatory": false, "default": 0 }
      }
    }
  },
  "edge_types": {
    "Knows": {
      "fields": {
        "since": { "type": "fixedpoint(0)", "mandatory": true }
      }
    }
  }
}
```

- **Field type** may be `integer`, `fixedpoint(s)` (scale `s` ∈ [0,18]), `boolean`, `string`, `identifier`, `list`, or `map`.  
- **Mandatory** fields must be present on every instance; optional fields may be omitted and, if omitted, take the `default` value if supplied.  
- The **type‑definition hash** is the SHA‑256 of the canonical JSON representation (keys sorted, no whitespace) and appears in the golden file as `"type_definitions_hash"`.

All IR must reference only types defined in this schema; otherwise the engine raises `INVALID_IR`.

---

### 2.3 Canonical Graph Serialization (new)

The **golden file** contains the graph state as a JSON object with two top‑level arrays:

```json
{
  "nodes": [
    { "id": "Person:1", "type": "Person", "fields": { "name": "Alice", "age": 30 } },
    { "id": "Person:2", "type": "Person", "fields": { "name": "Bob",   "age": 25 } }
  ],
  "edges": [
    { "id": "Knows:5", "type": "Knows", "src": "Person:1", "tgt": "Person:2",
      "fields": { "since": "2020.0" } }
  ]
}
```

- **Ordering:** `nodes` and `edges` are sorted by identifier using `ORDER_CANONICAL`.  
- **Fields:** keys inside each `fields` object are sorted lexicographically.  
- **Fixed‑point values:** serialized as strings with exactly `scale` fractional digits (e.g. `"12.5000"` for scale 4). For `scale = 0` the string contains no decimal point (e.g. `"42"`).  

The golden file also contains `"ir_schema_version": "1.0"` and the `"type_definitions_hash"`.

### 2.4 Expressions (unchanged)  

```
e ::= k | x | x.f | e1 ⊕ e2 | len(e) | to_fixed(e,scale) | to_integer(e)
⊕ ::= + | - | * | / | // | % | < | <= | > | >= | == | != | && | ||
```

All operations have **checked semantics** (overflow → fatal). Short‑circuit evaluation is required left‑to‑right for `&&` and `||`. **Dependency extraction** records reads from **both** operands regardless of the runtime short‑circuit result (conservative but deterministic).

**Additional operators (new):**  

- Unary negation `!e` (boolean).  
- Logical OR `||`.  
- Inequalities `!=`, `<=`, `>=`, `>`.  
- List literals `[e₁,…,eₙ]` and map literals `{"k₁":e₁,…}`.  
- Indexing `e₁[e₂]` (list or map lookup; out‑of‑bounds ⇒ fatal).

### 2.5 Patterns (unchanged)

```
P ::= ∅
    | MatchNode(x, type_name) · P
    | MatchEdge(x, type_name, src, tgt) · P
```

Patterns are enumerated in **lexicographic order of the tuple of bound identifiers** using `ORDER_CANONICAL` for each component (see §4).

### 2.6 Constraints (unchanged)

```
φ ::= True
    | e1 == e2
    | e1 < e2
    | φ1 && φ2
    | (φ)
```

All constraints are **re‑evaluated at COMMIT** (mandatory; see §5.4).

### 2.7 Let Bindings (unchanged)

```
B ::= ∅
    | Let(x, e) · B
```

Let bindings are evaluated during discovery; they do not affect match identity or `match_key`. Reads induced by `e` are recorded in the read‑trace.

```
a ::= CreateNode(x, type_name, {f₁:e₁,…})

    | DeleteEdge(e)
    | DeleteNode(x)
    | EmitEvent(event_type, [e₁,…])
```

### 2.9 Rule Definition (unchanged)

```
Rule ::= Rule(rule_id, base_priority, priority_scale, fairness_scale, P, φ, B, A)
```

### 3. Deterministic Ordering (ORDER_CANONICAL)

For any two values `x` and `y`:

- **Strings:** UTF‑8 bytewise lexicographic after NFC normalization.  
- **Identifiers:** compare `(type_name, sequence_number)` lexicographically.  
- **Lists:** element‑wise lexicographic.  
- **Maps:** compare keys in UTF‑8 order, then values recursively.  

`ORDER_CANONICAL` is used for:

- Pattern enumeration (see §5.1).  
- Sorting incident edges for implicit `DeleteNode` expansion.  
- `match_key` ordering.  
- Map literal iteration.  
- Tie‑breaking for min/max/sort.

---

### 4. Numeric Model (updated)

- **Integers:** signed 64‑bit.  
- **Fixed‑point:** scaled integers, scale ∈ [0,18] inclusive, serialized as strings with exactly `scale` fractional digits (scale 0 → no decimal point).  
- **Arithmetic rules:**  

| Operator | Promotion | Scale propagation | Rounding | Overflow |
|----------|-----------|-------------------|----------|----------|
| `+`, `-` | Integer → FixedPoint(0) if mixed | `max(scale_left,scale_right)` | truncation toward zero | fatal |
| `*` | Integer → FixedPoint(0) if mixed | `scale_left + scale_right` | truncation toward zero | fatal; if result scale > 18 → **FIXED_POINT_SCALE_OVERFLOW** (fatal) |
| `/` | Integer → FixedPoint(0) if mixed | `scale_left` | truncation toward zero | division‑by‑zero → **DIVISION_BY_ZERO** (fatal) |
| `//` | Integer division | – | floor division | division‑by‑zero → **DIVISION_BY_ZERO** (fatal) |
| `%` | Integer modulo | – | – | division‑by‑zero → **DIVISION_BY_ZERO** (fatal) |
| Comparisons | promotion as above | – | – | – |

- **Literal conversion:** `to_fixed(e,scale)` truncates toward zero; `to_integer(e)` truncates toward zero.

### 5. Operational Semantics (Small‑Step SOS)

The kernel executes via deterministic transitions over extended configurations that include ephemeral derivation artifacts. The official configuration is `<G, C, M_prev>`. The following rules describe the derivation steps; the overall transition `<G, C, M_prev> → <G', C', M_prev'>` is deterministic.

#### 5.1 DISCOVER  

`EvalPatterns(G, IR) = M` is the total set of matches obtained by:

1. Enumerating pattern bindings in **lexicographic order of the tuple of bound identifiers** (using `ORDER_CANONICAL` for each component).  
2. Evaluating constraints and let bindings left‑to‑right with required short‑circuit for `&&`.  
3. For each match `m` compute  

   ```
   match_key(m) = (rule_id, sorted_binding_list)
   ```

   where `sorted_binding_list` is the list of `(binding_name, binding_value)` pairs sorted by `binding_name` (UTF‑8) and then by `binding_value` using `ORDER_CANONICAL`.  

   `age(m) = if match_key(m) ∈ M_prev then M_prev[match_key(m)] + 1 else 0` (saturates at `INT64_MAX`).  

   The read‑trace `R_m` contains **all** reads performed during evaluation, including:

   - `NodeExistence(id, existence_version)`  
   - `FieldRead(id, f, field_version)`  
   - `ExtentRead(type, extent_version)`  
   - `AdjacencyRead(node, edge_type, dir, adjacency_version)`  
   - `EdgeExistence(edge_id, existence_version)`  

Transition:  

```
<<G, C, M_prev>, IR>  ⇒  <<G, C, M_prev, M>, IR>
```

#### 5.2 SELECT (with bounded retries)

Let `M_remaining = M`. Maintain a per‑tick `Rejected` set, initially empty.

Define  

```
score(m) = base_priority(m) * priority_scale(m) + age(m) * fairness_scale(m)
```

All arithmetic uses 128‑bit intermediate arithmetic; overflow saturates to `INT64_MAX` (or `INT64_MIN` for negative values).  

Total order for selection:

1. Higher `score` first.  
2. If tie, lexicographically smaller `match_key` (using the structured tuple comparison).  

Select `m* = argmax_{m ∈ M_remaining \ Rejected} score(m)`.  

If `M_remaining \ Rejected = ∅` **or** the number of retries reaches `MAX_RETRIES = |M|`, the tick ends with **NO_MATCH** (see §5.5).  

Otherwise, transition  

```
<<G, C, M_prev, M>, IR>  ⇒  <<G, C, M_prev, M, m*, Rejected>, IR>
```

#### 5.3 PLAN (Syntax‑Directed Compilation)

`Compile(IR, G, m*)` recursively compiles the rule’s action block `A` into a **Canonical Action Trace** `α̂` and a read set `R`. The judgment  

```
E ⊢ <A, G> ⇓ <α̂, R>
```

where `E` maps pattern variables to concrete identifiers from `m*`.  

**Base case (empty block):** `E ⊢ <∅, G> ⇓ <[], ∅>`  

**UpdateField:**  

```
E ⊢ <e, G> ⇓ <v, R_e>
x_id = E(x)
E ⊢ <A_tail, G> ⇓ <α̂_tail, R_tail>
--------------------------------------------------------------
E ⊢ <UpdateField(x, f, e) · A_tail, G> ⇓
   <[UpdateField(x_id, f, v)] · α̂_tail,
    R_e ∪ {FieldRead(x_id, f, field_version)} ∪ R_tail>
```

**DeleteNode (with implicit edge deletion):**  

```
x_id = E(x)
edges = GetIncidentEdgesSorted(x_id, G)   // sorted by edge identifier (ORDER_CANONICAL)
α̂_edges = [DeleteEdge(e) for e in edges]
R_edges = ⋃_{e∈edges} {
            AdjacencyRead(x_id, e.type, out, adjacency_version),
            EdgeExistence(e, existence_version)
          }
E ⊢ <A_tail, G> ⇓ <α̂_tail, R_tail>
--------------------------------------------------------------
E ⊢ <DeleteNode(x) · A_tail, G> ⇓
   <α̂_edges · [DeleteNode(x_id)] · α̂_tail,
    R_edges ∪ {NodeExistence(x_id, existence_version)} ∪ R_tail>
```

**CreateNode, CreateEdge, EmitEvent** – analogous structural rules, each recording the appropriate reads (see §4.4 for the complete read‑trace table).  

**Context‑freeness invariant:** Evaluation depends only on the subterm, the immutable environment `E`, and the fixed graph snapshot `G`.  

If compilation encounters a **non‑fatal validation error** (duplicate field update, missing mandatory field, etc.) the candidate `m*` is added to `Rejected` and SELECT is re‑invoked (subject to the retry bound).  

Transition:  

```
<<G, C, M_prev, M, m*, Rejected>, IR>  ⇒  <<G, C, M_prev, M, m*, Rejected, α̂, R>, IR>
```

#### 5.4 COMMIT (deterministic and mandatory)

**Premises**

1. **Version validation** – For every read `r ∈ R` the current version in `C` must match the version snapshot recorded in `r`.  
2. **Structural validation** –  
   - No duplicate `UpdateField` on the same `(id, f)`.  
   - No duplicate `DeleteEdge` on the same edge.  
   - All targets of `CreateEdge` exist in `G` or are created earlier in `α̂`.  
   - No dangling identifiers after applying `α̂`.  
   - **All constraints are re‑evaluated** against the post‑action graph `G_temp`. If any constraint fails, the match is rejected (non‑fatal).  
3. **Counter overflow pre‑check** – Any counter that would exceed `INT64_MAX` after increment is fatal (`COUNTER_OVERFLOW`).  

If any validation fails (non‑fatal) → add `m*` to `Rejected` and return to SELECT (subject to the retry bound). Fatal errors halt and rollback.

**Application**

- Apply each primitive action in `α̂` in order to a copy `G_temp`.  
- Update counters `C → C'` according to the **Version Increment Table** (see §4.4).  
- Emit events in the order they appear in `α̂`.  

**Match‑history update**

```
M_prev' = { match_key(m) → age(m) | m ∈ M }
```

All entries from the current discovery set are kept; entries whose `match_key` has not appeared for `K = 2³²` ticks may be garbage‑collected (deterministic pruning).  

**Result**

```
<<G, C, M_prev, M, m*, Rejected, α̂, R>, IR>  ⇒  <<G', C', M_prev'>, IR>
```

where `C'.tick_counter = C.tick_counter + 1`.

#### 5.5 NO_MATCH (deterministic)

If `M_remaining \ Rejected = ∅` **or** the retry bound is reached:

```
<<G, C, M_prev, M>, IR>  ⇒  <<G, C[tick_counter+1], M_prev'>, IR>
```

`M_prev'` is **identical to `M_prev`** (no clearing). Ages for entries not present in `M` are unchanged; entries that disappear from the graph are simply omitted from the new map (they are not retained).

### 6. Version Increment Rules (complete table)

| Operation | Extent | Predicate | Edge‑type | Edge‑predicate | Adjacency (src.out / tgt.in) | Existence | Field |
|-----------|--------|-----------|-----------|----------------|------------------------------|-----------|-------|
| **CreateNode** | +1 | +1 for each created field | – | – | – | set to 1 | set to 1 for each created field |
| **DeleteNode** | +1 | +1 for each field of the node | – | – | (handled by implicit DeleteEdge) | removed | removed |
| **CreateEdge** | – | – | +1 | +1 for each created field | +1 on src.out, +1 on tgt.in | set to 1 | set to 1 for each created field |
| **DeleteEdge** | – | – | +1 | – | +1 on src.out, +1 on tgt.in | removed | removed |
| **UpdateField (node)** | – | +1 for that field | – | – | – | – | +1 for that field |
| **UpdateField (edge)** | – | – | – | +1 for that field | – | – | +1 for that field |

All counters are **incremented atomically** during COMMIT; adjacency increments are deduplicated by the key `(node_id, edge_type, dir)` as described in §4.4.

### 7. Canonical Action Trace (CAT) Format

The CAT is a JSON array of objects, each representing a primitive action in the order of execution:

```json
[
  { "op":"CreateNode", "target":"Person:7", "type":"Person", "fields":{ "name":"Alice","age":30 } },
  { "op":"CreateEdge", "target":"Knows:5", "type":"Knows", "src":"Person:7", "tgt":"Person:2", "fields":{ "since":"2021.0" } },
  { "op":"UpdateField", "target":"Person:7", "field":"age", "value":31 },
  { "op":"EmitEvent", "event_type":"Greeting", "payload":["Hello","Alice"] }
]
```

The CAT is recorded in the golden file under `"committed_changes"` for each tick.

### 8. Error Model (unchanged, with added codes)

| Category | Example | Effect |
|----------|---------|--------|
| **Fatal** | counter overflow, division‑by‑zero, invariant breach, missing map key, index out of bounds, resource limit exceeded | Immediate halt, rollback to pre‑tick state, emit error snapshot |
| **Non‑fatal** | stale read, duplicate field update, missing target | Discard current match, add to `Rejected`, retry SELECT (subject to retry bound) |

**New error codes**  

- `FIXED_POINT_SCALE_OVERFLOW` – scale > 18 in any fixed‑point operation.  
- `RESOURCE_LIMIT_EXCEEDED` – any of the limits defined in §7.1 is exceeded.

### 9. Determinism Theorem (updated)

*Theorem:* For any configuration `<Σ, IR>` there is at most one `<Σ', IR>` such that `<Σ, IR> → <Σ', IR>`. Consequently, for a given initial state and IR, all conformant engines produce identical observable behavior.

*Proof sketch* (unchanged, now with the added deterministic rules for `NO_MATCH`, identifier allocation, pattern enumeration, and mandatory constraint re‑evaluation).

### 10. Conformance  

A conformant engine must:

1. Implement the SOS rules exactly as defined.  
2. Reject invalid IR (type errors, malformed identifiers, duplicate rule ids, etc.).  
3. Enforce all deterministic ordering, overflow checks, and version‑snapshot validation.  
4. Produce identical golden files for identical IR and initial state.  

The companion conformance test suite provides exact IR inputs and expected golden outputs.
