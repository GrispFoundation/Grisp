# Consensus Severity Ranking

## Tier 1 — Must Fix Before Implementation

These are specification-breaking issues.

### 1. Double Tick Advancement

The specification advances time in Rule 1:

```text
TICK:
T -> T+1
tick_counter -> tick_counter+1
```

and then again in COMMIT:

```text
⟨..., T+1, ...⟩
```

which causes logical time to advance twice.  

### Recommendation

Remove `T` entirely.

Use:

```text
tick_counter
```

as the sole time source.

State becomes:

```text
Σ = ⟨G, C, M_prev⟩
```

This simplifies the model and removes an entire category of synchronization bugs.

---

### 2. Read Validation Cannot Work

DISCOVER records reads:

```text
NodeExistence(id)
FieldRead(id,f)
```

but COMMIT requires comparison against:

```text
version recorded during DISCOVER
```

No version snapshot is actually stored.  

### Recommendation

Every dependency must record a version snapshot:

```text
NodeExistence(id, existence_version)

FieldRead(id, field, field_version)

ExtentRead(type, extent_version)

AdjacencyRead(node, edgeType, dir, adjacency_version)
```

Without this change, dependency validation is impossible.

---

### 3. Infinite Retry Loop

The specification says:

```text
discard m*
return to SELECT
```

but never removes the failing candidate from the candidate set. 

Therefore SELECT may repeatedly choose the same failing candidate forever.

### Recommendation

Introduce:

```text
M_remaining
```

or

```text
Rejected
```

for the current tick.

On failure:

```text
M_remaining := M_remaining \ {m*}
```

If empty:

```text
NO_MATCH
```

transition.

---

### 4. Missing Empty Match Transition

The specification states:

```text
If M empty → tick ends with no commit
```

but there is no SOS rule defining how this occurs. 

### Recommendation

Add:

```text
NO_MATCH
```

rule.

Example:

```text
M = ∅

────────────────

⟨G,C,M_prev⟩
→
⟨G,C[tick_counter+1],∅⟩
```

(or whatever final semantics you choose).

Without this, the machine can get stuck.

# Tier 2 — Determinism Threats

These are not immediate crashes but can cause different implementations to diverge.

### 5. Short-Circuit Evaluation Ambiguity

Several reviewers identified this independently. 

Current wording effectively permits:

```text

```

to either:

* skip B

Choose one:

#### Option A

Mandatory short-circuit:

```text
left-to-right
```

#### Option B

Always evaluate both operands.

Either is acceptable.

"Allowed" is not.

### 6. Pattern Enumeration Not Fully Defined

```text
ascending identifier order
```

but multi-variable matches require a total ordering over tuples.

```text
lexicographic ordering
```

Use:

The "Unified DSOS" approach correctly identifies the right mechanisms for a fully deterministic graph-rewrite calculus (optimistic concurrency via read traces, canonical ordering, and atomic commits). However, as the aggregated analyses make crystal clear, the v0.50 specification contains several mathematical contradictions and state-machine holes that will cause a native compiled implementation—especially in languages with manual memory management like Delphi—to either drift out of sync, livelock, or fragment the heap.

Here is the definitive consensus on what must be fixed and exactly how to resolve it so the kernel can safely power your GRISP v0.01 grammar.

---

### Phase 1: Fixing the Fatal State Machine Errors (Correctness)

These issues break the core structural operational semantics (SOS) and must be patched before writing any engine code.

**1. The Time Drift (Double Tick Increment)**

* **The Flaw:** Rule 1 increments both $T$ and $tick\_counter$. Rule 5 increments $T$ again. Time drifts out of sync.
* **The Consensus Fix:** Remove the concept of $T$ from the state model entirely. The state should be exactly $\Sigma = \langle G, C, M_{prev} \rangle$. The current tick is strictly defined as $C.tick\_counter$. The `TICK` rule is removed (or made a no-op guard), and the counter is incremented exactly *once* during the transition to $\Sigma'$.

**2. The Infinite Rejection Livelock**

* **The Flaw:** If a candidate $m^*$ fails a non-fatal validation (like a duplicate update), the spec discards it and re-invokes `SELECT`. But without removing $m^*$ from the pool, `SELECT` will pick the exact same highest-scoring match infinitely.
* **The Consensus Fix:** Introduce an ephemeral $M_{remaining}$ set per tick. On non-fatal rejection, update the set: $M_{remaining} := M_{remaining} \setminus \{m^*\}$.

**3. The "Empty Match" Void**

* **The Flaw:** If no matches are found, the system has no formal transition rule to advance time.
* **The Consensus Fix:** Define an explicit `NO_MATCH` transition rule. If $M = \emptyset$, increment $C.tick\_counter$, clear ephemeral derivation artifacts, and begin the next tick.

**4. Ghost Read Traces (Impossible Validation)**

* **The Flaw:** `DISCOVER` records that an element was read (e.g., `FieldRead(id, f)`), but `COMMIT` requires validating against the "recorded version." Because the integer version wasn't saved, validation is mathematically impossible.
* **The Consensus Fix:** The read trace $\mathcal{R}_m$ must explicitly store the version snapshot. Redefine entries as tuples: $\text{Read}(kind, target, version\_snapshot)$. For example: $\text{FieldRead}(id, f, v)$ where $v$ is the exact `field_version[id][f]` at the moment of discovery.

---

### Phase 2: Closing the Nondeterminism Gaps

To guarantee identical golden files across all implementations, edge cases in evaluation and ordering must be locked down.

**1. Short-Circuiting Must Be Mandatory**

* **The Flaw:** Allowing short-circuiting as "optional" for `&&` and `||` destroys determinism, as different engines will generate different dependency read sets ($\mathcal{R}_m$).
* **The Consensus Fix:** Make strict, left-to-right short-circuiting **mandatory**. If a logical condition is met, dependency extraction must immediately halt. Document that expressions inside `where` and `let` blocks must be pure functions with no side effects.

**2. Multi-Pattern Total Ordering**

* **The Flaw:** "Ascending identifier order" doesn't cover patterns binding multiple variables.
* **The Consensus Fix:** Define a total lexicographic order on the entire *tuple* of bound identifiers. For a pattern binding $(x, y, z)$, the order is determined by comparing the tuples component-wise using `ORDER_CANONICAL`.

**3. Fixed-Point Arithmetic Completeness**

* **The Flaw:** Missing rules for scale propagation and rounding.
* **The Consensus Fix:** Inline the numeric model. Define truncation toward zero for rounding. For scale propagation:
* Addition/Subtraction: $scale = \max(scale_{left}, scale_{right})$
* Multiplication: $scale = scale_{left} + scale_{right}$
* Division: $scale = scale_{left}$



---

### Phase 3: Native Performance & Architecture Upgrades

These fixes protect the engine from memory blowouts and optimize it for high-performance execution.

**1. The `match_key` JSON Bottleneck**

* **The Flaw:** Mandating a "canonical JSON serialization" of bindings to create a `match_key` will cause devastating heap fragmentation in Object Pascal due to allocating and destroying thousands of strings per tick just to resolve ties.
* **The Consensus Fix:** Redefine the `match_key` as a native, structured binary tuple: `(rule_id, [(var_name, type, seq), ...])`. Compare these tuples lexicographically in memory. Only use canonical JSON serialization when emitting the final golden file.

**2. Unbounded Memory Growth (`M_prev`)**

* **The Flaw:** Tracking the age of every match indefinitely will eventually consume all available RAM. Furthermore, the scoring math ($base \times scale + age \times fairness$) will cause a fatal 64-bit integer overflow if a match survives too long.
* **The Consensus Fix:** Use saturating arithmetic for the fairness score (if it exceeds `INT64_MAX`, it clamps to `INT64_MAX` instead of crashing). Implement an eviction policy to drop matches from $M_{prev}$ if they haven't been seen in a defined number of ticks.

---

### Phase 4: Compatibility with GRISP Grammar v0.01

Your proposed grammar maps almost perfectly to the Canonical IR. Applying the fixes above makes the kernel fully compatible, with two important notes for the compiler:

1. **`let_block` Integration:** The grammar naturally supports `let` statements. Because `let` variables often read graph state, you must explicitly document that expressions evaluated in a `let_block` contribute to the $\mathcal{R}_m$ read trace during the `DISCOVER` phase, even if they don't alter the `match_key` identity.
2. **`CreateNode` Validation:** Your grammar allows `CreateNode` with a `map_literal`. The spec states all fields are mandatory. Your engine's `PLAN` phase must treat a missing mandatory field in a `CreateNode` action as a static, non-fatal validation error (triggering the $M_{remaining}$ rejection loop), preventing invalid nodes from ever reaching `COMMIT`.

| Issue | Consensus Fix |
|-------|----------------|
| **Short‑circuit “allowed”** | Change to **“required left‑to‑right short‑circuit”**. For dependency extraction, **evaluate both operands** of `&&`/`||` (i.e., read set always includes both), but logical result short‑circuits. This keeps traces deterministic. |

**Consensus – Core Fix Set for GRISP Deterministic Kernel (v0.51)**  

Below is a single, ordered list that combines all the strongest recommendations from the analyses. Implementing these items will eliminate the fatal contradictions, close the SOS, and make the kernel fully compatible with the Grisp v0.01 grammar.

| Priority | Issue (short description) | Fix (what to change) |
|----------|---------------------------|----------------------|
| **1** | **Double‑tick increment** – `T` and `tick_counter` both advance. | Remove `T` from the state. Keep only `C.tick_counter` as the authoritative tick. Increment it exactly once per successful commit (or once per tick if you keep a pre‑commit counter). |
| **2** | **Missing empty‑match transition** – no rule when `M = ∅`. | Add a `NO_MATCH` rule that increments the tick counter (or leaves it unchanged if you keep a single counter) and clears temporary artefacts. |
| **3** | **Read‑trace lacks version data** – validation cannot compare versions. | Extend every read entry to include the version value captured during DISCOVER (e.g., `NodeExistence(id, v)`). Define a canonical `ReadTraceSchema`. |
| **4** | **Infinite reselection loop** – a failing match is never removed. | Introduce a per‑tick `Rejected` set (or remove the match from `M`). `SELECT` operates on `M_remaining = M \ Rejected`. When `M_remaining` becomes empty, fall back to `NO_MATCH`. |
| **5** | **Underspecified total order for multi‑binding patterns**. | Define lexicographic ordering on the full binding tuple `(id₁, id₂, …)` using `ORDER_CANONICAL` for each component. Document this in the DISCOVER rule. |
| **6** | **Short‑circuit dependency ambiguity** – `&&`/`||` may change the read set. | Make short‑circuit **required** for logical result but **mandatory** for dependency extraction: both operands are evaluated for the purpose of building `ℛ_m`. |
| **7** | **Canonical `match_key` serialization** – JSON rules are incomplete. | Provide a precise algorithm: (a) NFC‑normalize strings, (b) sort map keys by `ORDER_CANONICAL`, (c) serialize identifiers as `type:seq` with decimal `seq` (no leading zeros), (d) emit minified JSON (no whitespace). |
| **8** | **Fixed‑point arithmetic incompleteness** (promotion, rounding, scale). | Inline the full numeric model: promotion of Integer → FixedPoint(0) for all operators, result scale = `max(lhs, rhs)` for `+`/`-`, `lhs_scale+rhs_scale` for `*`, `lhs_scale` for `/`; rounding = truncation toward zero; overflow checks as defined. |
| **9** | **Score overflow** – `base*scale + age*fairness` can overflow 64‑bit. | Compute scores in a 128‑bit intermediate and **saturate** to `INT64_MAX` (or `INT64_MIN` for negative). Never fatal; treat saturated scores as the highest/lowest possible rank. |
| **10** | **Adjacency counter double‑counting** (DeleteNode vs DeleteEdge). | Remove the “+1 per incident edge (after dedup)” entry from the `DeleteNode` row. Rely on the explicit `DeleteEdge` actions (which already increment adjacency). |
| **11** | **Unbounded `M_prev` growth**. | Add a retention policy: prune entries whose age exceeds a configurable `AGE_MAX` (e.g., 1 M) or that have not appeared for `N` ticks. Document that pruning does not affect determinism because ages are capped. |
| **12** | **Missing type system / IR validation**. | Insert a formal typing section: primitive types, field declarations, expression typing rules, rule‑level well‑formedness (unique rule ids, mandatory fields, no duplicate field names). |
| **13** | **Event payload evaluation timing**. | Fix the semantics: evaluate all payload expressions **during PLAN** and store the concrete values in `α̂`. COMMIT merely emits those stored values. |
| **14** | **Direction enum for adjacency version**. | Define `dir ∈ {in, out, undirected}` and state how each is updated. |
| **15** | **No‑op write definition**. | Define a no‑op as “new value identical to old value under canonical serialization”. No version counters are incremented for no‑ops. |
| **16** | **`RESOURCE_LIMIT_EXCEEDED` without limits**. | Add a resource‑limit section (max size of `M`, max depth of `M_prev`, max length of `α̂`). Exceeding any limit triggers the error. |
| **17** | **Unused version counters (`extent_version`, `ordering_dependency_version`)**. | Either remove them from the state model or integrate them into validation (e.g., `extent_version` must be unchanged for any extent read). |
