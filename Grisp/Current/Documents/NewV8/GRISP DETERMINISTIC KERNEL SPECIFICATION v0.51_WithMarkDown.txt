# GRISP DETERMINISTIC KERNEL SPECIFICATION – Version 0.51

## Unified DSOS (Deterministic Structural Operational Semantics) Edition  

### (Consensus‑Based Revision, incorporating fixes from v0.50 analysis)

---

### Preamble

This specification defines the GRISP Deterministic Kernel as a **closed, formally deterministic graph‑rewrite calculus**. It supersedes all previous versions (v0.49, v0.50, v0.51, v0.60) and resolves their architectural inconsistencies by unifying pattern matching, dependency tracking, action compilation, and commit into a **single structural operational semantics with trace projection**.

For identical Canonical IR and identical initial state, all conformant engines MUST produce identical observable behavior:
- Committed state transitions
- Emitted events
- Golden file output

All normative rules are mandatory. No hidden nondeterminism, runtime inference, or dual semantic models are permitted.

---

## 0. Core Principles

1. **Single semantic object** – State is a tuple `⟨G, C, M_prev⟩` with no hidden runtime artifacts.
2. **Determinism by construction** – All choice points eliminated via total orders and structural recursion.
3. **Read effects as derivation** – Dependencies are induced by syntax‑directed translation, with version snapshots recorded at read time.
4. **Canonical Action Trace (CAT)** – The execution trace is a projection of the compilation derivation.
5. **Atomic commit** – Validation, application, and counter update form a single, rollback‑able step.

---

## 1. State Model

A configuration is:

```
Σ = ⟨G, C, M_prev⟩
```

- **G** – Typed property graph (nodes, edges, fields, identifiers). No nulls, all fields mandatory.
- **C** – Counters (signed 64‑bit integers):
  - `tick_counter` (starts at 0) – the authoritative tick number.
  - Sequence counters per node/edge type (start at 0 or max+1 from initial state)
  - Version counters:  
    `extent_version[type]`,  
    `predicate_version[type][field]`,  
    `edge_type_version[type]`,  
    `edge_predicate_version[type][field]`,  
    `adjacency_version[node][type][dir]`,  
    `existence_version[node/edge]`,  
    `field_version[element][field]`
- **M_prev** – Previous match set: a map from `match_key` to `age` (integer). Initialized empty.

**Invariants** (checked after each commit):
- No dangling edges (source/target exist)
- No dangling identifier references (recursively through lists/maps)
- All declared constraints satisfied
- No cycles in identifier references (detected via visited set)

## 2. Canonical IR Syntax (Inductive)

The IR is a deterministic, canonical JSON format. Below is its inductive definition.

### 2.1 Expressions

```
e ::= k                           // literal (Integer, FixedPoint(s), Boolean, String, Identifier)
    | x                           // variable (pattern binding or let)
    | x.f                         // field access
    | e1 ⊕ e2                     // binary operator
    | len(e)                      // list length
    | to_fixed(e, scale)          // conversion to FixedPoint
    | to_integer(e)               // truncation to Integer

⊕ ::= + | - | * | / | // | % | < | <= | > | >= | == | != | && | ||
```

All operations have checked semantics (overflow → fatal). **Short‑circuit evaluation is required left‑to‑right** for `&&` and `||`. Dependency extraction includes **both operands** for the purpose of building the read trace (i.e., the read set is the union of reads from both sides, regardless of the runtime short‑circuit result).

### 2.2 Patterns

```
P ::= ∅
    | MatchNode(x, type_name) · P
    | MatchEdge(x, type_name, src, tgt) · P
```

Patterns are enumerated in **lexicographic order of the tuple of bound identifiers** (in pattern order), using `ORDER_CANONICAL` for each component.

### 2.3 Constraints (where clause)

```
φ ::= True
    | e1 == e2
    | e1 < e2
    | φ1 && φ2
    | (φ)
```

`e1` and `e2` are boolean‑typed expressions. `&&` follows the same short‑circuit and dependency rules as §2.1.

### 2.4 Let Bindings

```
B ::= ∅
    | Let(x, e) · B
```

Evaluated during discovery; do **not** affect match identity or `match_key`. Reads induced by `e` are recorded in the read trace.

### 2.5 Actions

```
a ::= CreateNode(x, type_name, {f1: e1, ...})
    | CreateEdge(x, type_name, src, tgt, {f1: e1, ...})
    | UpdateField(target, field, e)
    | DeleteEdge(e)
    | DeleteNode(x)
    | EmitEvent(event_type, [e1, ...])
```

### 2.6 Rule Definition

```
Rule ::= Rule(rule_id, base_priority, priority_scale, fairness_scale, P, φ, B, A)
```

- `rule_id` – string matching `[A-Za-z_][A-Za-z0-9_-]*`
- Priorities: non‑negative integers
- `A` – action block (sequence of actions)

## 3. Deterministic Ordering (ORDER_CANONICAL)

For any two values `x` and `y`:

- **Strings**: UTF‑8 bytewise lexicographic, after **NFC normalization**.
- **Identifiers**: compare `(type_name, sequence_number)` lexicographically (type_name UTF‑8, then numeric).
- **Lists**: element‑wise lexicographic.
- **Maps**: compare keys in UTF‑8 order, then values.

Used for:
- Pattern enumeration (tuple ordering)
- Sorting incident edges for implicit `DeleteNode` expansion
- `match_key` ordering
- Map literal iteration
- Tie‑breaking for `min`/`max`/`sort`

---

## 4. Numeric Model

- All integers: signed 64‑bit.
- Fixed‑point: scaled integers, scale 0–18 inclusive, serialized as **strings** with a decimal point and exactly `scale` digits (e.g., `"42.0"` for scale 0, `"12.5000"` for scale 4).
- Arithmetic rules (fully defined here):
  - **Promotion**: Integer → FixedPoint(0) when combined with FixedPoint in any operation (`+`, `-`, `*`, `/`, comparisons).
  - **Scale propagation**:
    - `+`, `-`: `result_scale = max(scale_left, scale_right)`
    - `*`: `result_scale = scale_left + scale_right`
    - `/`: `result_scale = scale_left`
  - **Rounding**: truncation toward zero (for division and conversion).
  - Overflow and division by zero → **fatal**.
  - Fixed‑point division uses big‑integer intermediates, checked on final result.
- Literal conversion: `to_fixed(e, scale)` truncates toward zero; `to_integer(e)` truncates toward zero.

## 5. Operational Semantics (Small‑Step SOS)

The kernel executes via **deterministic transitions** over extended configurations that include ephemeral derivation artifacts. The official configuration is `⟨G, C, M_prev⟩`. The following rules describe the derivation steps; the overall transition `⟨G, C, M_prev⟩ → ⟨G', C', M_prev'⟩` is deterministic.

### Rule 1: DISCOVER

Define `EvalPatterns(G, IR) = M` as the total set of matches obtained by:

- Enumerating pattern bindings in **lexicographic order of the tuple of bound identifiers** (pattern order).
- Evaluating constraints and let bindings left‑to‑right with required short‑circuit for `&&`.
- Each match `m` contains:
  - `match_key` = structured tuple `(rule_id, sorted_binding_list)` compared by `ORDER_CANONICAL`.
  - `bindings` (identifier bindings only)
  - `let_values` (diagnostic only)
  - **read trace** `ℛ_m` of all graph elements accessed, **including version snapshots**:
    - `NodeExistence(id, existence_version)`
    - `FieldRead(id, f, field_version)`
    - `ExtentRead(type_name, extent_version)`
    - `AdjacencyRead(node_id, edge_type, dir, adjacency_version)`
    - `EdgeExistence(edge_id, existence_version)`

Age assignment:

```
age(m) = if match_key(m) ∈ M_prev then M_prev[match_key(m)] + 1 else 0
```

Ages saturate at `INT64_MAX` (no overflow).

Transition (ephemeral):

```
⟨⟨G, C, M_prev⟩, IR⟩ ⇒ ⟨⟨G, C, M_prev, M⟩, IR⟩
```

### Rule 2: SELECT (with retry semantics)

Let `M_remaining = M`. Also maintain a per‑tick `Rejected` set, initially empty.

Define:

```
score(m) = base_priority(m) × priority_scale(m) + age(m) × fairness_scale(m)
```

Computed using **128‑bit intermediate arithmetic**; if the result exceeds `INT64_MAX` it saturates to `INT64_MAX`; if below `INT64_MIN` it saturates to `INT64_MIN`. Overflow never fatal.

Total order:
1. Higher score first.
2. If tie, lexicographically smaller `match_key` (using structured tuple comparison, not JSON).

Select `m* = argmax_{m ∈ M_remaining \ Rejected} score(m)`.

If `M_remaining \ Rejected = ∅`, the tick ends with **no commit** (see Rule 6).

Transition:

```
⟨⟨G, C, M_prev, M⟩, IR⟩ ⇒ ⟨⟨G, C, M_prev, M, m*, Rejected⟩, IR⟩
```

### Rule 3: PLAN (Syntax‑Directed Compilation)

Define `Compile(IR, G, m*)` by structural recursion over the rule’s action block `A`. It produces a **Canonical Action Trace** `α̂` (primitive action sequence) and a **read set** `ℛ`.

The judgment:

```
ℰ ⊢ ⟨A, G⟩ ⇓ ⟨α̂, ℛ⟩
```

where `ℰ` is the environment from `m*` bindings.

**Base case (empty block):**

```
ℰ ⊢ ⟨∅, G⟩ ⇓ ⟨[], ∅⟩
```

**UpdateField:**

```
ℰ ⊢ ⟨e, G⟩ ⇓ ⟨v, ℛ_e⟩   x_id = ℰ(x)   ℰ ⊢ ⟨A_tail, G⟩ ⇓ ⟨α̂_tail, ℛ_tail⟩
────────────────────────────────────────────────────────────────────────────
ℰ ⊢ ⟨UpdateField(x, f, e) · A_tail, G⟩ ⇓ ⟨[UpdateField(x_id, f, v)] · α̂_tail,
                                            ℛ_e ∪ {FieldRead(x_id, f, field_version)} ∪ ℛ_tail⟩
```

**DeleteNode (with implicit edge deletion):**

```
x_id = ℰ(x)
edges = GetIncidentEdgesSorted(x_id, G)   // ORDER_CANONICAL by edge identifier
α̂_edges = [DeleteEdge(e) for e in edges]
ℛ_edges = ⋃_{e∈edges} {AdjacencyRead(x_id, e.type, out, adj_version), EdgeExistence(e, existence_version)}
ℰ ⊢ ⟨A_tail, G⟩ ⇓ ⟨α̂_tail, ℛ_tail⟩
──────────────────────────────────────────────────────────────────────────────
ℰ ⊢ ⟨DeleteNode(x) · A_tail, G⟩ ⇓ ⟨α̂_edges · [DeleteNode(x_id)] · α̂_tail,
                                    ℛ_edges ∪ {NodeExistence(x_id, existence_version)} ∪ ℛ_tail⟩
```

**CreateNode, CreateEdge, EmitEvent** – similar structural rules, each recording appropriate reads and version snapshots. For `EmitEvent`, payload expressions are evaluated to values during PLAN; `α̂` stores the evaluated payload.

**Context‑freeness invariant:** Evaluation depends only on the subterm, the immutable environment `ℰ`, and the fixed graph snapshot `G`.

If compilation encounters a non‑fatal validation error (duplicate field update, missing mandatory field), the candidate `m*` is added to `Rejected` and SELECT is re‑invoked.

Transition:

```
⟨⟨G, C, M_prev, M, m*, Rejected⟩, IR⟩ ⇒ ⟨⟨G, C, M_prev, M, m*, Rejected, α̂, ℛ⟩, IR⟩
```

### Rule 4: COMMIT

**Premises:**

1. **Version validation:** For every read `r ∈ ℛ`:
   - `NodeExistence(id, v)` → node exists and `existence_version[id] == v`.
   - `FieldRead(id, f, v)` → `field_version[id][f] == v`.
   - `ExtentRead(type, v)` → `extent_version[type] == v`.
   - `AdjacencyRead(node, type, dir, v)` → `adjacency_version[node][type][dir] == v`.
   - (Analogous for edge reads.)

2. **Structural validation:**
   - No duplicate `UpdateField` on same `(id, f)`.
   - No duplicate `DeleteEdge` on same edge.
   - All targets exist (or are created earlier in `α̂`).
   - No dangling identifiers after applying `α̂`.
   - All constraints satisfied (re‑evaluated if desired, but version validation suffices; the spec leaves this optional but deterministic).

3. **Counter overflow pre‑check:** For every counter that would be incremented, ensure `post_value ≤ INT64_MAX`. Overflow → fatal.

If any validation fails (non‑fatal) → add `m*` to `Rejected` and go back to SELECT. Fatal errors halt and rollback.

**Application:**

- Apply each step in `α̂` in order to a **copy** `G_temp`.
- Update counters `C → C'` according to the version increment table (see §6). Adjacency increments are deduplicated using the earliest occurrence in `α̂` (scan left‑to‑right, maintain a set of already‑processed `(node, edge)` pairs).
- Emit events in the order they appear in `α̂` (payloads already evaluated, stored in `α̂`).

**Match history update:**

```
M_prev' = { match_key(m) → age(m) | m ∈ M }
```

(All matches from the discovery snapshot, not only the committed one.)

Transition:

```
⟨⟨G, C, M_prev, M, m*, Rejected, α̂, ℛ⟩, IR⟩ → ⟨⟨G', C', M_prev'⟩, IR⟩
```

where `C'.tick_counter = C.tick_counter + 1`.

### Rule 5: NO_MATCH (Empty Match Set)

```
M_remaining \ Rejected = ∅
──────────────────────────────────────────────────────────────
⟨⟨G, C, M_prev, M⟩, IR⟩ → ⟨⟨G, C[tick_counter+1], M_prev'⟩, IR⟩
```

`M_prev'` is implementation‑defined but deterministic: either `M_prev` unchanged or cleared (recommended: keep `M_prev` to preserve ages across idle ticks).

## 6. Version Increment Rules (Derived from Compile)

The following table shows counter changes **only when a mutation actually occurs** (No‑Op writes do nothing). These are consequences of the structural compilation semantics.

| Operation              | extent | pred(node) | edge_type | edge_pred | adjacency (source.out, target.in) | existence | field_vers |
|------------------------|--------|------------|-----------|-----------|-----------------------------------|-----------|------------|
| CreateNode             | +1     | +1 (each field in supplied map) | -         | -         | -                                 | set to 1  | set to 1 each |
| DeleteNode             | +1     | +1 (each field) | -         | -         | (handled by expanded DeleteEdge)  | removed   | removed    |
| CreateEdge             | -      | -          | +1        | +1 (each field in supplied map)   | +1 source.out, target.in          | set to 1  | set to 1 each |
| DeleteEdge             | -      | -          | +1        | -                                 | +1 source.out, target.in          | removed   | removed    |
| UpdateField (node)     | -      | +1 (that field) | -         | -         | -                                 | -         | +1 (that)  |
| UpdateField (edge)     | -      | -          | -         | +1 (that field)                   | -                                 | -         | +1 (that)  |

- `+1 (each field)` – increment for every field of that type (only for actually supplied fields in Create).
- Adjacency increments occur once per edge per endpoint, deduplicated using the earliest occurrence in `α̂`.

## 7. Canonical Serialization (Golden File)

Output is UTF‑8 JSON with lexicographically sorted keys, no extra whitespace.

- **Integer** – JSON number, no leading zeros.
- **FixedPoint** – JSON string with decimal point and exactly `scale` digits (e.g., `"42.0"` for scale 0).
- **Boolean** – `true`/`false`.
- **String** – double‑quoted, escaping `\`, `"`, `\n`, `\r`, `\t`, other controls as `\uXXXX`.
- **Identifier** – string containing `type:seq` (e.g., `"Person:5"`).
- **List** – `[e1,e2,...]`.
- **Map** – `{"k1":v1,"k2":v2,...}` (keys sorted by ORDER_CANONICAL).

### Top‑level golden file structure

```json
{
  "ir_schema_version": "1.0",
  "type_definitions_hash": "<hex>",
  "initial_state": { ... },
  "ticks": [ ... ],
  "final_state": { ... }
}
```

If a fatal error occurs, the `"ticks"` array is replaced by an `"error"` object.

### Tick record

```json
{
  "tick_number": 0,
  "selected_match_key": { "rule_id": "...", "bindings": {...} } | null,
  "committed_changes": [ ... ],
  "events": [ { "rule_id": "...", "payload": ... } ]
}
```

### Error object

```json
{
  "code": "COUNTER_OVERFLOW",
  "context": { "location": 0, "snapshot": [...] },
  "state": { ... },
  "tick": 0
}
```

Allowed error codes:  
`INTEGER_OVERFLOW`, `DIVISION_BY_ZERO`, `COUNTER_OVERFLOW`, `INDEX_OUT_OF_BOUNDS`, `MISSING_MAP_KEY`, `INVALID_IR`, `INVARIANT_VIOLATION`, `ADJACENCY_COUNTER_MISSING`, `RESOURCE_LIMIT_EXCEEDED`.

## 8. Determinism Theorem

**Theorem:** For any configuration `⟨Σ, IR⟩`, there is at most one `⟨Σ', IR⟩` such that `⟨Σ, IR⟩ → ⟨Σ', IR⟩`. Consequently, for a given initial state and IR, all conformant engines produce identical observable behavior.

**Proof sketch:**

- `EvalPatterns` is a total function over `G` and `IR` – ordering fixed by tuple lexicographic order.
- `ComputeAge` is a pure lookup.
- `SELECT` uses a total order (score descending, then `match_key` ascending); `Rejected` set ensures progress.
- `Compile` is defined by structural induction; each clause yields a unique `(α̂, ℛ)` due to canonical ordering and context‑freeness.
- `COMMIT` validation and application are pure functions, with version snapshots enabling deterministic staleness checks.
- `NO_MATCH` handles empty candidate set deterministically.
- No other transition rules exist.

Thus the transition relation is deterministic.

## 9. Error Model

| Category | Example | Effect |
|----------|---------|--------|
| **Fatal** | counter overflow, division‑by‑zero, invariant breach, missing map key, index out of bounds, resource limit exceeded | Immediate halt, rollback to pre‑tick state, emit error snapshot |
| **Non‑fatal** | stale read, duplicate field update, missing target | Discard current match, add to `Rejected`, retry SELECT |

Fatal errors use the codes in §7. Non‑fatal errors are not recorded in golden files.

## 10. Conformance

A conformant engine **must**:

- Implement the SOS rules exactly as defined.
- Reject invalid IR (type errors, malformed identifiers, duplicate rule ids, etc.).
- Enforce all deterministic ordering, overflow checks, and version snapshot validation.
- Produce identical golden files for identical IR and initial state.

All normative content in this specification is mandatory.  
The companion conformance test suite provides exact IR inputs and expected golden outputs.
