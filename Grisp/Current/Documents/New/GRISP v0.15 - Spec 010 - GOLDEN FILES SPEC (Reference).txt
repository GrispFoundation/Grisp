---------------------------------------------------------------------
1. PURPOSE
---------------------------------------------------------------------
Golden Files v0.15 provide **canonical reference examples** for:

  - Canonical IR manifests
  - Expression AST structures
  - Rule evaluation
  - Transaction execution
  - Trust propagation
  - Boundary Contract requests/responses
  - AI IR lowering
  - Capability checks
  - Event emission
  - Hook execution

Golden Files are **not normative**, but they are the **ground truth**
for:

  - engine conformance tests
  - compiler validation
  - regression testing
  - cross‑implementation consistency
  - documentation examples

They ensure all GRISP implementations behave identically.

---------------------------------------------------------------------
2. STRUCTURE OF GOLDEN FILES
---------------------------------------------------------------------
Golden Files are organized into sections:

  - manifest/
  - rules/
  - expressions/
  - transactions/
  - trust/
  - boundary/
  - ai_ir/
  - capabilities/
  - events/
  - hooks/

Each section contains one or more `.golden.json` files.

---------------------------------------------------------------------
3. GOLDEN FILE FORMAT
---------------------------------------------------------------------
Golden Files MUST use:

  - canonical JSON
  - sorted keys
  - deterministic formatting
  - UTF‑8 encoding
  - no comments
  - no trailing commas

Example header:

{
  "_golden": {
    "version": "v0.15",
    "description": "Basic task assignment example"
  },
  ...
}
